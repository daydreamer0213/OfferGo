# 按原简历结构编辑

用户要求：简历修改应参考简历本身的章节、顺序和项目层级，不划成“基础资料 / 常用资料”。本轮只改简历工作室的编辑呈现，不重新生成或改写用户的简历。

## 设计与边界

- 按正文里实际存在的原标题分区，例如个人优势、专业技能、工作经历、项目经历、教育经历和资格证书；不补造缺少的章节，不重新排序。
- 项目经历内有明确项目标题及日期时，按原项目分成子块；无法可靠区分就保留整块。
- 无标题的开头单独保留，未知内容全部保留。没有明确结构时继续提供全文编辑。
- 分区编辑是现有完整正文的视图。保存、自动保存、复制、导出、恢复、冲突和启用仍沿用原有完整正文及版本机制。
- 保留“编辑全文与章节标题”入口，允许用户调整结构。已启用版本的所有编辑入口都只读。
- 沿用现有页面样式，改善间距和标题层级；不新增编辑器依赖、模型调用、数据库字段或接口。

## 执行与检查点

1. **先固定回归**：合成简历含原始章节、两个项目、教育和自定义显式标题；先看到旧界面缺少分区导致的失败。
2. **实现最小分区视图**：按原文切片，保留空行和顺序。单独编辑一块只替换这一块，完整正文始终即时同步。全文编辑和恢复本机内容后重建分区。
3. **验证已有能力**：修改后立即导出或离开；保存期间继续输入；失败后刷新恢复；过时备份由用户决定；启用只读及副本继续编辑。检查其他章节逐字未变。
4. **看实际页面**：用独立 D 盘测试数据查看当前简历的章节、项目层级、桌面/窄屏和深色样式；自查可读性及错误，修正本轮明确缺陷。
5. **收尾复盘**：独立审查改动、运行相关回归、展示可点击的实际页面。记录完成内容与边界，不把界面通过当成内容质量提升，也不扩展到其他模块。

每个检查点只回答：是否让用户更容易找到并修改目标段落，是否保住全文和原有操作。若新增工作不影响这两项，本轮不继续扩展。
