# 真实消息同步验收与修复

**目标：** 用户在现有 Edge 点击“同步最新消息”，两个启用平台都被实际检查；简历邀请得到发送按钮及贴合语境的短回复。

**依据：** v1.4.1 真实验收中，BOSS 消息页处于 discarded 状态，CDP `/json/list` 不包含它，智联完成后整体错误地报告 completed。智联真实来信“你好，公司最近在积极寻找新伙伴，如果你感兴趣，可以发送简历聊聊看～”及简历邀请产生了询问岗位内容的草稿。

**方案：** 复用原浏览器连接和消息调度。浏览器适配器只恢复指定窗口中符合消息 URL 的休眠标签页；通过原生 Target 附着取得页面身份，再后台重新加载原页。控制器在消息页缺失时尝试恢复并重新列举，仍缺失时保留已有平台成果并明确未完成。简历请求解析保留薪资、面试等实质问题，剔除随简历邀请出现的招聘寒暄。

**边界：** 不新增浏览器窗口、平台标签页或运行依赖；不切换前台；不发送真实消息或简历；不改数据库结构；不覆盖 v1.4.1 冻结产物。

## 执行顺序

1. 给 `tests/message_requested_actions_smoke.js` 增加真实招聘邀请与邀请附带薪资、时间问题；先确认失败，再修 `src/core/message_requested_actions.js`。
2. 给 `tests/browser_transport_smoke.js` 增加休眠标签页恢复测试：同窗口、消息 URL 才重新加载，跨窗口及非消息页面不加载，错误后断开附着，不调用前台切换或创建标签页。再修改 `src/adapters/browser/cdp.js`，复用现有连接超时和清理逻辑。
3. 给 `tests/dashboard_message_discovery_smoke.js` 增加缺页恢复及一个平台缺失、另一个成功的检查；修 `src/dashboard/message_discovery_controller.js` 和对应提示。
   工作区建立也先尝试恢复休眠页，再决定是否创建缺失页，防止下一步确认操作产生重复标签页。
4. 运行上述检查和完整离线门禁；在 D 盘准备独立候选运行环境，用已有数据备份进行真实 Edge 验收，检查两个平台进度、消息内容、邀请动作和前台是否被打断。
5. 记录实际结果及尚未授权的外部动作；通过才切换验收版本。

## 效果标准

- 无法读取启用平台时不能声称全部同步完成。
- 休眠的原消息页能在后台恢复，没有新增重复消息页。
- 单纯简历邀请回复简短自然，不另问已展示的岗位内容或虚构简历发送渠道。
- 同一条邀请中的薪资、面试安排、项目问题仍得到独立处理。
- 用户已有未回复消息、编辑草稿和平台身份保持正确。

实际复测另外覆盖了 BOSS 带显示时间的“你好！方便发简历？”：时间戳不能把寒暄变成独立问题。已有邀请草稿的修复必须跳过用户编辑、已复制形成记忆、已确认待发送或已发送的草稿。
