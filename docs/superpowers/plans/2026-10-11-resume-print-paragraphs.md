# 简历打印段落修复计划

> **For agentic workers:** Use executing-plans to implement this finite task in the existing linked worktree; use an independent read-only review before committing.

**Goal:** 修复已有简历打印页面的条目跨页断句，让标题与后文保持在一起，不修改任何候选事实或生成结果。

**Architecture:** 仅在 `renderResumePrintPage(text)` 中根据原有空行、列表标记、常见明确章节标签和行尾带日期区间的经历行分块；保留每行原文与顺序，并使用浏览器原生分页规则。过长段落仍可跨页，避免无法打印整段。

**Tech Stack:** 已有 Node.js、HTML/CSS、Playwright 与 pdfjs-dist；不安装新依赖。

## 原因、方案与边界

实际旧输出把全文放在一个 pre-wrap 文本块中，第二页出现孤立句尾，第三页从项目描述中间开始。共享打印函数没有段落边界，文本导出与编辑保存本身没有丢失内容。

选择按已有格式分块与原生分页。只调整字号会掩盖跨页问题；新增简历语义解析或模型重写会超出打印职责。此修复不猜测硬换行是否应合并，保留导入换行，行数较多仍可由用户编辑原稿改善。

- 空行、独立列表项、常见明确章节标签、行尾包含起止日期的经历行构成已有格式边界；首行短中文姓名单独显示。普通短续句和正文中部年份不能误分为标题。未识别的其他标题保留普通正文显示，不做语义重写。
- 正文段落尽量不拆页；短标题及经历标题与下一段保持在一起；超长段落允许正常跨页并保留至少两行。
- 不改保存、启用、文本导出、画像、匹配输入、模型提示、模型配置和平台行为。
- 所有私有简历、失败 PDF、运行证据和新打印文件留在 D 盘，Git 只包含通用代码、合成检查与本计划。
