## 已确认的问题

一份此前未用于当前筛选的完整真实岗位，通过普通 Edge 提交一次。原生首次请求设置 4096，截断后唯一内置恢复设置 8192；两次 HTTP 均成功，但输出额度全部用于思考，最终答案均为零。请求的完整简历、JD 和系统提示一致，原六份有效结果没有变化。该记录是分析失败，不是岗位不匹配，也不是第七份有效判断。

前六份当前有效结果的保存响应显示：多数在 4096 内完成；另一份首次截断后在 5501 输出 tokens 内完成。此次两次截断证明当前上限可以阻止答案完成，但尚不能证明增加上限必然完成。官方 Chat Completions 文档允许更大的 max_tokens；实际响应 usage 已直接证明当前请求的思考占用该额度。模型随机性仍然存在。

## 方案选择与代价

选择只扩大 DeepSeek V4 开启思考时、因 MODEL_OUTPUT_TRUNCATED 触发的唯一恢复请求：8192 → 16384。首次仍为 4096，非截断结构恢复仍为 4096，非 DeepSeek V4 或关闭思考的截断恢复仍为 8192。复用现有 MAX_ADAPTIVE_RESPONSE_TOKENS 和模型集合，不新建重试层。

其他方案是提高所有首次请求额度，或降低思考强度。前者扩大所有任务的潜在用量；后者改变推理条件，可能影响判断质量，需要另行实验。本次完整资料、系统提示、推荐标准、模型、思考强度、JSON 模式及校验均保持；仍最多两次调用，账户授权/余额/429、取消和终止失败的边界保持。

受影响任务的两次调用输出上限从 12288 增至 20480，多 8192、约 66.7%；正常首次成功任务不变。实际用量、耗时和完成结果单独记录，不能把上限当成实际费用或耗时。恢复仍使用现有超时上限，超过后保留失败，不继续扩大或新增第三次请求。
