# 三模块实际使用缺口修复

依据：2026-10-04 虚拟用户实测；从 b44da87 开始。用户已同意继续落实报告中的六项整改。

原则：复用现有应用服务、消息上下文与页面；不改数据库结构、平台读写边界、模型协议，不删除历史草稿，不停用其他合法简历版本。测试数据、浏览器资料和导出证据放 D 盘。

## 实施与验收

- [x] 消息回归：正常介绍邮件能力应通过；擅自转邮箱仍拒绝；HTTP 200 needs_fact 应刷新到下一问题；新来信覆盖当前操作建议但保留旧草稿。
- [x] 修改 message_reply_contract 的渠道判断、消息页面成功状态及 controller 恢复时的消息组选择。优先按收件箱最新消息标识选组，避免编辑旧草稿改变顺序；无上下文的历史记录保留兼容。
- [x] 面试：当前问题上方显示上一题的一条改进；报告中的重练建议可跳到对应重答框。详细历史仍可展开，不中断连续答题。
- [x] 简历：使用现有全文表单导出文字版或打印页（浏览器可保存 PDF）；导出提交当前编辑内容，不能读到尚未自动保存的旧稿。明确启用不会更新平台附件。打印页只包含简历，转义用户文字，不含后台分析。
- [x] 简历选择：只标一份默认参考，其他可用版本保留；本轮选择仍冻结。排序沿用 store 的最近更新时间规则，与消息参考正文保持一致。
- [x] 针对原有 HTTP、前端脚本和应用服务补必要检查，先观察失败再修复；相关离线检查通过。
- [x] 隔离 Edge 复走消息补资料、来信更新、面试反馈与重练、简历编辑/文字导出/打印版；记录结果和截图，检查导出正文与最新编辑相同。
- 完整离线门禁在提交冻结后执行；结果以同日使用体验回执指定的 gate-receipt.json 为准。实现报告与验证限制已记录。

文件范围：src/core/message_reply_contract.js；src/dashboard/message_discovery_controller.js、message_discovery_view.js；src/dashboard/pages/mock_interview.js、resume_optimization.js；src/dashboard/server.js（仅复用现有简历表单的导出分支）；对应已有测试及文档。不引入排版库或新默认版本数据库字段。
