# 面试经历确认来源：有限修复计划

> **For agentic workers:** Use executing-plans to implement task by task. Reuse the existing isolated checkout. The current task has no new delegation requirement; do not spawn workers merely to execute this plan.

**Goal:** 阻止明确承认虚构的面试材料经编辑后成为可复用的真实经历，同时保留正常新增、定性结果及混合回答中可分离的真实部分。

**Architecture:** 复用实际 confirmEvidence 的来源校验和现有经历表，不把评分好坏作为真实性判定。先固定实际应用输入与可选择来源的边界，再在面试确认入口做有界修复；共享手动资料入口不因原简历没有内容而被收紧。

**Tech Stack:** 现有 Node.js、SQLite、原生面试服务及普通 Edge；无需新依赖或额外模型审核调用。

## 已有授权与约束

- 沿用已确认详细计划中的“实际缺陷→有限共同修复→准确版本检查→实际流程验收”，完整原四步不替换为本计划。
- 测试项目内部次数额度和轮次间等待可临时放行，不等待午夜、不重复请求该授权。随机节奏、周期休息、串行锁、检查点、共享计数及真实平台异常停止保留；正式策略不改。
- 所有虚构反例只进入 D 盘独立虚拟库，零真实资料写入。既有模型控制及失败保留，不能覆盖或改写旧结果。
- 改进判断不能套用二元式规则：improved=false 不等于虚假；没有精确指标、不在原简历、职责名称不同都不能自动拒绝用户补充。当前准备方法也不得在生成时被冒充为历史成果。
- 当前是已证明缺陷的修复准备。本文没有宣称来源识别算法已经闭合，也没有宣称产品已经修复。

## 事实和方案比较

已证明：实际 confirmEvidence 仅检查来源子串，明确自认编造的整段回答及去掉免责声明的编辑版均保存，并进入下一次 retryTurn 的真实输入。与此同时，可从混合回答选择真实定性部分，后续修复必须保留。证据见[C 来源控制](../reports/2026-10-12-C-contradictions-and-confirmation-boundary.md)。

| 方案 | 影响 | 选择 |
| --- | --- | --- |
| 在面试来源入口核对明确非事实声明及所选原话，允许可分离真实部分 | 对应已证明根因；需要验证声明覆盖范围和来源选择体验 | 优先继续设计和零模型验证 |
| 拒绝所有低评分、未知指标或简历未列出的补充 | 会误伤正常经历和实际新信息，违背现实判断 | 不采用 |
| 每次确认再调用一个模型判真伪 | 增加调用、恢复路径和误拒；不能证明事实本身 | 不采用 |
