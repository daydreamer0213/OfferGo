# 模拟面试故事准备：有限改造计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. 以下复选项均为待实施，不是完成记录。

**状态：** 根据用户“接下来怎么改”的提问形成具体方案；本轮没有修改生产代码、调用模型或运行功能验收。

**Goal：** 产品先根据简历为各块重要工作整理可讲述的故事初稿，用户可以修改、补充和重开，再围绕故事练习深入追问。

**Architecture：** 在现有模拟面试模块内增加独立的故事准备稿，复用简历资料冻结、模型适配器、问答反馈、复盘和重练。准备稿独立保存，开始练习时把所选故事的当时版本冻结进既有会话；不把准备稿伪装成面试回答或已确认经历。

**Tech Stack：** 现有 Node.js、SQLite、服务端页面与模型配置，无新增运行依赖。

## 一、已确认的要求

- 产品承担提炼、组织和表达工作，用户不必先写好完整故事。
- 每块重要工作都应有故事；按实际工作组织，不按 PDF 换行机械拆分。
- 故事包含责任、问题与情境、决策和行动、选择原因、结果、反思或经验。
- 产品先交付已有材料能支撑的初稿，关键事实缺失时再针对性补充，不先给用户一张必填大表。
- 产品也应帮助梳理决策取舍、表达经验总结；建议性的解释清楚呈现为可供用户选择和调整的思路，不能冒充已发生的事实。
- 深入追问围绕故事与用户实际回答；JD 定制属于可选加分项，通用准备无需岗位。
- 旧会话、回答、复盘和已确认经历保留。个人资料及验收数据只放 D 盘，不提交 Git。

设计依据：[模拟面试设计](../../mock_interview_design.md)。

## 三、用户完成一轮准备的流程

1. 打开模拟面试，沿用现有简历选择，默认看到“根据简历准备故事”。有已保存准备稿时先展示，打开页面本身不调用模型。
2. 主动点击后，系统按重要工作整理故事。页面先显示故事标题和简短概览，展开一条后阅读自然连贯的初稿，以及少量需要补充的提示。
3. 用户可直接改故事，也可补充情况后让系统重新整理这一条。其他故事与已保存修改保留。
4. 保存后可关闭、刷新、重开，继续使用同一份稿件；无需重新生成。
5. 选择想练的故事，进入“深入练习”：先练介绍这部分工作，再依据实际回答追问决策、原因、做法、结果或反思。可只练一条，不要求所有故事都补齐才开练。
6. 沿用已有反馈、复盘和重练。选了目标岗位时，再加入该 JD 的针对性问题。

页面主线是准备、修改、练习。来源依据、更多细节及岗位定制放在次级位置，避免再次形成密集文字页。

## 四、四个实施阶段

### 阶段 1：先交付一份能读、能讲的故事初稿

**改动范围：** `src/core/mock_interview.js`、`src/adapters/models/structured.js`、`src/application/mock_interview/index.js`、`src/storage/schema.js`、`src/storage/mock_interview_store.js`、`src/dashboard/server.js`、`src/dashboard/pages/mock_interview.js`。数据库沿用 `src/storage/migrations.js` 的现有迁移机制。

- [ ] 在既有服务增加准备动作，复用 `buildFrozenContext` 的简历脱敏、版本、来源哈希与证据编号；生成准备稿时不启动问答会话。
- [ ] 增加故事整理模型任务。模型按实质工作归组，输出每条故事的稳定编号、标题、简历依据、故事正文及待补充提示。正文沿六段逻辑组织成自然讲述，不输出空标题或只有关键词的问题清单。
- [ ] 校验输入归属、简历版本、证据引用及输出结构；内容是否讲清决策与原因另用实际样例评价，不能以 JSON 字段齐全替代。
- [ ] 用一张准备稿表保存身份、源资料快照/哈希、故事 JSON、编辑版本号、生成操作编号与时间。沿用现有归属检查和操作结果查询，不搭建通用内容管理或多层版本框架。
- [ ] 同一面试页增加“根据简历准备故事”及初稿展示。已有准备稿直接读取；生成失败保留旧稿及已有修改，明确显示失败，不返回虚构的成功稿。

**本阶段回归：** 在既有核心、服务、存储与页面检查中加入“准备而不出首题”“无岗位生成并读取三条稿”“非法来源不保存”“旧稿在生成失败后保留”的对应行为案例。先确认缺口，再做最小实现并跑对应检查，不等最后阶段才测试。

**交付与通过信号：** 一份包含三块重要工作的样例简历，能得到覆盖三块工作的真实初稿。故事能讲明本人工作、问题、决策原因与结果；缺材料处有针对性的提示，不扩大责任、不编造数字。不选岗位也能完成。

### 阶段 2：让准备稿可修改、可补充、可重开

**改动范围：** 复用阶段 1 的存储、服务、模型任务及同页表单，不另建编辑器产品。

- [ ] 每条故事提供简单正文编辑和保存。编辑版本检查阻止旧页面覆盖新稿；跨候选人、跨简历身份不允许误存。
- [ ] 提供“补充情况并重新整理这一条”。传入当前稿、当前补充和原来源，只更新所选故事；保留其他故事，失败时不覆盖任何已保存内容。
- [ ] 保留原生成内容与当前修改内容，便于区分来源；普通保存不调用模型。明确主动的整理动作才调用模型，响应丢失先查询已有操作结果，不盲目重复生成。
- [ ] 简历换版后明确区分新旧准备稿，不把旧稿默认为新简历内容；用户仍能打开旧稿。
- [ ] 保存准备稿用于练习，不自动写入跨模块的已确认经历库；不为每处文字编辑增加逐句确认。

**本阶段回归：** 扩展存储、服务及页面检查，实际保存后重新读取；核对相邻故事未变、整理失败未覆盖、旧版本保存被拒、同一操作恢复不重复生成。模拟错误发生在真实业务调用边界，不以源码文字检查代替。

**交付与通过信号：** 修改一条故事并保存，刷新及关闭重开后内容一致；补充后只更新该故事；旧稿、其他故事与原简历保持。至少覆盖一次失败后恢复和一次旧版本保存冲突。

### 阶段 3：把故事真正接到深入追问

**改动范围：** 现有应用服务 `startSession/generateStep`、核心题目契约、模型任务及面试页；复用既有会话上下文存储。

- [ ] 启动时核对准备稿归属及版本，选择故事，将所选内容和版本冻结进会话。之后修改准备稿不改写已开始的训练。
- [ ] 首题承接所选工作，让用户介绍项目或该部分工作。后续从真实回答找值得了解的决策、理由、实施、结果或反思；保留既有上一答引用与职责边界检查。
- [ ] 调整考查摘要和主题进度，使其围绕所选故事；不强制为了覆盖旧五类主题转到无关问题。本次沿用现有轮次、反馈、复盘、重练和错误恢复机制。
- [ ] 准备稿不能作为用户已回答的内容计分，也不能自动成为已确认事实。用户可以使用仍有待补充事项的稿件练习。
- [ ] `resume_general/job_specific` 均保留。JD 问题作为补充，旧会话缺少准备稿字段时继续按旧上下文运行，不要求先补稿。

**本阶段回归：** 用服务与契约检查捕获实际传给模型的故事版本与上一答，修改准备稿后重新读取原会话，核对快照未变；旧上下文不含故事字段时仍可继续，并覆盖通用无岗位入口。

**交付与通过信号：** 用户实际改过的故事进入训练，首题与追问确实围绕这条工作及其回答；没有强制选择岗位。改稿不会改变历史会话；旧通用、岗位会话和报告仍能打开、继续或重练。

### 阶段 4：走通一次完整体验并收口

- [ ] 汇总前三阶段已扩展的 `mock_interview_contract_smoke.js`、`mock_interview_store_smoke.js`、`mock_interview_service_smoke.js`、`dashboard_mock_interview_smoke.js` 直接行为检查；页面旅程复用 `three_module_user_experience_journey.js` 补齐完整串联。新增分支先用旧行为复现缺口，再实现，不为静态文案或字段存在写测试。
- [ ] 聚焦核对：逐块故事覆盖；未知事实处理；编辑/保存/重开；版本与身份隔离；失败不丢稿及操作去重；所选稿用于追问；新旧会话兼容。只断言实际行为，不把模型 mock 当真实内容质量。
- [ ] 在隔离 D 盘资料中，通过正常页面做一轮少量真实体验：生成故事 → 补充/修改 → 保存 → 重开 → 选一条故事练习介绍和追问 → 查看反馈并重练。事前按用户标准核对原材料，不抓招聘页、不外发。
- [ ] 实际初稿必须易懂、可讲，重要工作不遗漏；深入追问必须增加对项目掌握程度的了解。失败保留并按具体原因处理，不为了拿到漂亮稿反复生成或做多模型比较。

**收口信号：** 用户可从简历获得准备成果、修改保存并重开，且能围绕故事完整练习。代码检查、界面排版与实际文字效果分别说明；未验证的效果不标通过。此次改造不自动发布、安装升级或覆盖正式资料。

## 五、避免再次陷入局部调试

- 每阶段结束最多用 2 分钟回答：用户新增了什么能力；还缺什么；是否偏离本计划；唯一下一步是什么。
- 每三轮总体复盘一次；连续两轮没有新增可用能力或获得能改变决策的证据，提前复盘并停止机械重复。
- 首个检查点必须是可查看的故事初稿，不能只交付模型契约、数据库或更多文档。
- 不因个别次要措辞自动重开一轮。优先修真实阻断、实质遗漏、责任/成果失真与用户指出的问题。
- 不改岗位筛选，不采集更多招聘资料，不重建题库、评分体系、全局编辑器或候选人知识库。既有资料全部保留。
- 阶段完成按上述交付物判断，不用测试数量、代码行数或计划更新换算产品完成率。
