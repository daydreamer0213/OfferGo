# 明确假设情境的职责检查修复计划

> 执行方式：复用现有隔离工作区，按 executing-plans 在当前会话逐项执行；完成后按 requesting-code-review 做独立只读复查。用户已授权持续推进既定整改，本任务落实已复现共同根因，不引入新产品方向或外部动作。

**Goal:** 明确“假设你负责……”的情境题可以原样进入面试；真实职责声明继续要求关联证据，不能整题免检。

**Architecture:** 只修改原有职责检查。遍历每处职责表述，紧邻“假设／假如／如果／设想（由）”的角色分配按明确假设处理；其余表述继续使用原证据检查。假设文本也不能作为过去实际职责的证据。

**Tech Stack:** Node.js 22、既有原生校验器／面试应用服务／SQLite、原测试入口。无新依赖或模型请求。

## 设计依据和范围

准确起点：文档HEAD `6afc44ab4282dc551d5f1a4e8ac5ad8fe8717436`，产品源码与 `28476bdf464cf80b9dd31a65d88cdc62e46fd28c` 相同。原C专项第四答实际首输出和零模型单变量回放证明假设角色被当成真实履历；其余覆盖和反馈问题不由此推断已解决。

选用局部角色判断，保留原题及考查能力。另两种方案不采用：让模型换词需要额外调用且掩盖本地误判；只要整题含“假设”便放行会漏掉同题的真实职责声明。该修复处理明确紧邻的假设角色，不宣称覆盖所有自然语言情境。既有字面职责提取的其他限制继续保留，后续依据实际失败再评估。

不改变模型／提示、题目预算、真实资料、岗位筛选策略、BOSS访问方式或风控；不重跑终结A/B/C轮，不自动确认经历，不替换原8800／8801服务或安装版。所有生成证据在D盘。
