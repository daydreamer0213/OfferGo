# OfferGo 按情境验收实际效果的实施计划

用户已批准：按具体用户任务审查各模块，确认真实问题后修复，持续推进至最终人工验收。起点为 `2de65e9`。此前效果标准继续适用，本计划补充情境粒度及证据，不重写产品架构。

## 验收方法与约束

- 先固定每个案例的输入、用户目标、合格结果和不合格反例，再运行产品；不以当前输出倒推合格标准。
- 案例按会改变处理结果的事实、意图和状态区分，不以同义句数量充当覆盖。
- 模拟资料、真实模型生成、生产应用服务、Edge 页面观察分别记录；模型替身只证明流程，保存输出重放只证明当前校验和显示。
- 每个结论绑定具体案例及版本；未验证的情境不能写成通过。修复后复测原失败和相邻正常情况。
- 复用当前隔离工作树、已有标准、合成资料及测试入口。大型结果留在 D 盘；不改用户业务数据、模型设置、SQLite 版本或对外协议。
- 不引入通用语义拦截平台、评分模型、新运行依赖或更多个人信息门槛。确实需要用户决定的安排应询问；已知普通求职事实应直接回答。
- 真实平台仅在需要验证页面前提时最小只读检查；未经具体授权不发送消息、简历或投递。

## 逐情境效果标准

### 消息与回复

| 情境 | 合格结果 | 失败反例 |
| --- | --- | --- |
| HR 指定时间，用户尚未确认 | 询问用户该时间是否可行，不能擅自承诺 | 直接答应；反问 HR 已经给出的时间 |
| HR 指定时间，已知该时段可行 | 自然确认这次安排；仅缺必要安排时补问 | 反复要求确认已知资料；答无关兴趣表达 |
| 指定时间冲突，用户有替代时段 | 说明原时段不方便并提出可用时段 | 仍确认原时段；把改期当拒绝机会 |
| HR 问什么时候方便，时间未知 | 向用户问可用日期和时段，补充后给出具体安排 | 只回复“有空”；反问 HR 什么时候安排 |
| HR 问什么时候方便，有有效时间 | 直接给可用时段，不把到岗日期当面试时间 | 用过期“明天”；答“两周到岗” |
| 面试安排加项目问题/简历邀请 | 所有真实关切均被回答，简历有独立动作 | 单一标签吞掉其他问题 |
| 只是提到面试系统、条件性后续 | 回答真正问题，不视为已经约面 | 生成无关约面确认 |
| 知识更正、撤回或范围不适用 | 下一次只用当前有效且相关的资料 | 用旧值、跨岗位承诺或未采用草稿 |

### 模拟面试

| 情境 | 合格结果 | 失败反例 |
| --- | --- | --- |
| 通用训练首题 | 从实际履历选能考察能力的题，明确个人贡献 | 询问到岗、薪资等登记事项；预设没有的职责 |
| 岗位专项首题 | 对照 JD 工作及简历，问适配能力或真实工作情境 | 只有岗位关键词，没有考察理由 |
| 回答空泛 | 指出当前回答缺什么，追问一项关键个人行动/判断 | 空泛夸赞；转走而未考到能力 |
| 回答已具体完整 | 承认已说明内容，必要时深入取舍或切换主题 | 再追问同一已答问题，复盘说已知信息缺失 |
| 用户明确没做过/只是协助 | 保留边界，可问相近经历或明确的假设情境 | 继续追问“你当时怎么主导”，要求编历史 |
| 没有量化指标但有定性验证 | 根据实际验证评价，数字不是统一门槛 | 所有题都要求百分比；没数字就判不会 |
| 重答只是更长/离题 | 不判进步，说明仍未回答哪里 | 按长度、术语或礼貌判断改善 |
| 重答补了有效行动/证据 | 说明新增内容解决哪个原缺口，仍保留其他缺口 | 每次同一模板反馈，原答和新答混淆 |

### 简历优化

| 情境 | 合格结果 | 失败反例 |
| --- | --- | --- |
| 通用粗糙稿 | 清楚呈现本人做什么、方法和交付，保留正常章节 | 为教育加“相关经历”；每句机械 STAR |
| 岗位专项 | 强调有依据的相关经历，不借 JD 发明能力 | 堆关键词；把相近经验变成本人做过 |
| 原稿已清楚 | 允许保持，完整可编辑及导出 | 为显示工作量把具体信息改抽象 |
| 团队成果/跨项目技术 | 保留贡献和归属、指标口径 | 把团队成果或另一项目技能挪给本人 |
| 用户补充、更正或撤回 | 按有效资料更新相应内容，不误改其他章节 | 历史旧信息重新出现；事实丢失 |

### 其余模块

分别核对首次/再次使用（资料复用与新操作）、搜索方案（真实岗位名称与已读取条件）、发现岗位（覆盖、重复及恢复）、岗位解释（职责与相关经历可理解）、沟通清单（来源、确认与结果）、求职体检（样本成熟与建议有据）、设置/诊断/启动（状态真实、反馈及时、错误可恢复）。沿用已验证证据，只补缺失或受修复影响的情境；旧数据不证明新策略质量，模拟成功不证明真实平台写入。
