# 岗位判断顶层运输元信息的有限修复

## 已确认问题与范围

一份新完整 JD 的普通 Edge 首次分析已终结失败：首答五个判断字段完整且来源绑定有效，但模型额外生成了 `provider`、`model`、`usage`，其中模型身份与实际请求不一致。严格结构检查因此使用唯一恢复；恢复以 `length` 结束且无正文。共两次实际 HTTP，不再重放此岗位，不将失败记为不匹配或有效质量样本。

实际模型身份和请求用量来自配置与运输响应，不能信任生成正文的这三项。拟仅删除这三个已知顶层元信息字段，保留五个核心判断字段、档位、措辞和来源校验。未知非空附加判断、错误来源、缺失字段、截断、认证及限流处理保持现有边界；不增加请求、篇幅或语义重试。独立复查先判断这一边界是否合理。

## 执行与验收

1. 保留完整 JD、原简历、首答、唯一恢复、失败记录和原八条岗位。只读核对实际页面及重开：失败提示与不匹配分开，完整 JD 仍可查看。已完成，检查脚本对批量字段的首次错误单独保存。
2. 在现有原生适配器回归中加入实际失败形态的虚拟材料检查：生成错误的模型身份和零用量时，五核心字段完全相同、仅一次请求、不采用这些元信息。先确认当前实现失败，再改最少源码。保留未知非空字段、缺失档位及错误来源的反例，不把诊断原值写入日志。
3. 只修改当前归一化路径与必要回归。原生产提示、输入、4096/8192 篇幅与两次请求上限不变。用原完整材料与原首答做零 HTTP 本地回放，只证明格式兼容，不回填操作库或冒充重新成功分析；具体解释偏差另列。
4. 完成独立窄审查、准确源码完整浏览器必跑门禁和同 SHA CI，再用普通 Edge 验证保存结果的显示与重开。所有生成数据放 D 盘，临时本地页关闭后返回同一 Codex。
5. 更新阶段记录和逐平台覆盖账。此次新增正文属于已采集但分析失败，正式覆盖不降低、失败不丢弃。保持随机间隔和半小时以内完整休息；测试超过半小时的阶段休息可适当缩短并记录原值及实等，正式策略不改。整体质量、原四步和最终人工验收继续开放，不发布。

## 明确停止条件

未知非空输出、有效判断字段变化、来源变松、额外联网、原数据改变或准确门禁失败时，停止该修复的采纳并保留证据。不以重复模型输出或扩大详情抓取来使此修复看似成功。
