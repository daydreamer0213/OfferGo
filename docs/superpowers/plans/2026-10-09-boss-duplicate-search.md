# BOSS 重复搜索页整理

这是四步验收第 1 步发现问题后的最小修复，不是新的搜索模式。

## 已确认的问题

- 实际 Edge 有两个同窗 BOSS 搜索页，广州及地铁条件相同，关键词不同；当前只读页面显示“广州、工作区域(14)”。
- 代码按标签编号选择搜索页，不比较筛选条件，也不关闭重复页。受控复现中，默认页编号在前时会选中默认页，忽略另一页的广州和地铁条件。
- 当前实际两页的条件相同，不能声称本轮已经搜错范围。

## 实施约束

1. 复用正常 Dashboard 的工作区整理入口、已有 BOSS 搜索 URL 规范化规则和平台任务互斥机制。
2. 只整理当前工作台同窗、后台的 BOSS 搜索页；消息页、岗位详情、其他窗口和其他平台不关闭。
3. 优先保留实际筛选条件更多的一页；条件相同优先保留当前绑定页，否则稳定保留一页。保留完整 URL，不改关键词或条件。
4. 有运行中、暂停或待继续的 BOSS 找岗/沟通工作流时不整理。正在执行的平台任务占用互斥锁时跳过，不影响现有流程；找岗已结束、仅等待本地清单确认不占用浏览器，允许整理。
5. 每次关闭前复核目标、保留页、完整 URL、窗口及前台状态；关闭后确认目标消失、保留页和前台未变。异常立即停止，不重复关闭结果不明的页。
6. 不改变采集数量、岗位详情覆盖、访问节奏、数据库结构或外部沟通权限。

## 验证顺序

- 先保存失败回归：默认页排在前仍须保留条件更多的页；重复页必须由产品关闭。
- 覆盖相同条件、当前绑定、其他窗口、前台页、页面条件变化、关闭失败、平台任务占用和暂停工作流。
- 检查现有工作区、浏览器传输、固定标签绑定及架构门禁。
- 用正常候选 Dashboard 在现有 Edge 完成整理，核对原广州及地铁条件、前台页面和后续读取结果。
- 运行完整离线浏览器门禁、提交推送并核对同一提交 CI；更新四步清单。
