# 三模块缺口补齐与面试考察边界

基线：35a845b。用户已授权思考补法后实施；沿用上一轮核心设计，不再设置额外批准步骤。

## 实施选择

只修改现有资料选择、回复学习与面试服务，不新建知识系统。仅增加提示词不足以修复已复现的数据连接错误；向量库或额外检索服务目前也没有必要。

1. 从有效、用户确认的经历中投影明确的在职、到岗、所在城市、薪资等资料，按确认时间与现有资料合并。只解析明确陈述，不推测；原记录撤回后投影立即消失。复用候选人事实规则，保持 schema 37，无新表。
2. 改写回复的完整文字仍保持原岗位范围；在现有事实整理模型调用中，额外提取最多三段可跨岗位复用的个人经历。逐字来源必须来自用户改写，混合回答中的薪资、时间或对特定公司的承诺不进入经历段。复用现有经历表的 manual 来源，source_id 使用 reply-edit:<memoryId> 明确区分。修改或撤回答案时同步更新/撤回其经历段，不保留已失效的信息。整理失败不阻塞已授权发送。
3. 共用资料选择器增加少量通用能力主题的同义识别，保留文字匹配、范围校验和输入字数上限。覆盖解决问题、协作、个人贡献、成果和求职动机，不写针对某份简历的技术词替换表。
4. 专项简报读取实际的 coreResponsibilities、coreRequirements、requirementMatches、roleGaps、questionsToVerify 和相关简历证据，兼容旧字段；完整 JD 保留。
5. 面试训练考察自我介绍、真实贡献、问题解决、业务/技术理解、合作取舍、成果与岗位适配。到岗时间、期望薪资、当前是否在职等流程确认不是训练题；离职动机和空档解释仍可在简历相关时训练。每次出题传入已考察主题、已问问题与剩余重点；不强制三题覆盖五主题。拒绝完全重复和纯流程确认题，针对这两类错误最多重新生成一次，不丢弃旧回答或凭空填充题目。

## 验收

- 确认的明确求职状态能用于 HR 回复；撤回后不再可用；新手填资料不被旧经历覆盖。
- 同一段改写中的经历能供另一岗位使用，而针对原岗位的条件仍限定原岗位；撤回、修改和重复完成不产生残余或重复经历。
- “碰到难题怎么处理”能找到“复现故障、定位原因”的旧经历，岗位/公司限定资料仍不能越界。
- 实际岗位分析结构进入专项重点；允许不同专业和岗位资料，不依赖单份测试简历。
- 不使用到岗、薪资等凑面试题；简历上的离职解释、能力缺口可正常练；重复题反馈后换题，正常追问不被误伤。
- 相关回归、完整离线门禁、匿名内容样例和可用浏览器页面分别记录，不能用测试数量冒充内容质量验收。
