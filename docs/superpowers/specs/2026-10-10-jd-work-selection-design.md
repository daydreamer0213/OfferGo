# 岗位初筛：完整 JD 工作判断的有限生产设计

日期：2026-10-10。依据当前 `1b8335f2c2108040959379125e9ade73c4496eb7` 源码和本轮实验。本文锁定实施方向，不表示已实施、已通过 CI 或已完成人工验收。私有简历、JD 原文、请求和回复仅保留在 D 盘，不入仓库。

## 1. 产品职责与判断原则

岗位初筛回答三个实际问题：岗位主要做什么；候选人的真实工作、交付和有意义的相邻经验怎样支持它；这份机会是否值得投入投递。它不替 HR 做录用资格证明审查。

- 按正常完整简历理解最高已完成学历，不猜隐藏硕士。
- 普通本科未写全日制可按现实常态初筛，证明核验留给后续 HR；不因普通遗漏统一降档或要求补字。
- 相关专业结合实际软件、Agent 等工作理解，不使用专业名称精确相等的门槛。
- 未列技能不等于绝对不会；实际相邻交付可以支持机会。但不能把通用工具使用伪装成另一个专业工作的成熟实践。
- 明确不可替代的已知冲突仍需说明；普通年限、专业、优先项和竞争力差距不机械转为关闭条件。
- 同一 JD 独立招聘多个方向时，条件属于被选择的方向。不能把算法方向的届别或学历套给独立社招后端。
- 区分重大错配、技术失败和解释瑕疵。档位在参考范围内，不代表解释全部正确。

## 2. 实验结论及适用范围

业务方法选用 C11：完整 JD、完整且绑定同版本的脱敏简历、结构化画像、已确认匹配卡、实际有效偏好及本次日期一起判断。五字段任务的提示哈希为 `68d4b9396a3911d2793b540f22796548b3fa4c60f7d74c3779effe4cc7b0180e`。

关键六类情形三轮方向稳定。首轮十二真实完整 JD 都产生可保存结果，普通学制遗漏和专业名称差异未作统一封顶；实际年限和主交付差距仍被解释。旧矩阵曾把普通资格未知统一压成慎投，也曾因资料充分仍无结论。

原真实保留组保存为 7/8，不通过完整保存入口：一次截断耗用恢复机会后，第二次回复多出空输入数组而拒收。原失败保留，没有把后续规范化结果回写成事前通过。最小修正仅清除输出根部已知输入数组的空回显，五个工作判断字段、来源、解释、建议不变；非空额外字段、未知字段、缺字段和错误引用继续失败。63 项零请求实际回复与反例检查通过。

修正后的新增保留组先按未参与当前输出调试的历史完整 JD、每平台最早四个 ID 选择并独立判读，再冻结运行。七个前置允许岗位均保存工作判断；另一个明确超出城市范围的岗位，两次模型格式失败仍保留，最终排除依据是城市前筛。生产应在前筛排除后结束，无需请求匹配。新增组没有用于业务提示调整，但历史材料可见，不能称全球盲测。

同任务、同首个真实请求输入的关闭思考核对未通过效果入口：明确届别冲突仍被建议确认；另一个岗位两次坏 JSON 无结果。因此本次实现和效果验收配置使用 DeepSeek v4 Flash、开启思考、high。保留既有用户模型设置，不在运行时暗中覆盖思考开关；推荐新配置开启思考，旧关闭配置的质量差异必须在迁移和最终验收中明确。

这些证据支持有限实现，不支持全市场准确率。个别解释仍有卡片/正文年限展示顺序、过强的缺少经验措辞等问题。合成短 JD 的工作判断与最终展示分开统计；当前 120 字门槛还会拦住部分有具体职责的短材料，不把这些计为完整链路通过，不填字凑长。

## 3. 三层流程及停止位置

1. **用户范围与平台可执行条件**：复用城市、工作类型、薪资、用户排除、有效链接、活跃/刷新、账号状态等已有明确边界。排除直接保存原因；待刷新保留待办；两者都不调用工作匹配。
2. **完整 JD 工作匹配**：进入范围的岗位按实际工作及所选独立方向判断。届别/学生身份等 JD 条件及其证据保留给本层，不作整份 JD 的全局预筛。完整材料弱匹配也应给四档结论，不能伪装成技术失败。
3. **后续 HR 确认**：学制证明、细节凭证及最终录用核验留在后续交流。初筛不生成必须逐项核实的资格清单。

BOSS 只读、背景双固定标签、串行、`trusted_pane`、随机节奏、冷却、检查点及异常立即停止等行为不改。推荐与默认勾选不构成发送授权，原不确定发送不重放。

## 4. 输入、输出及校验

新增 `whole_jd` 语义模式。输入包含原始 JD 全文及卡片字段、完整同版本脱敏简历、画像、确认卡、从实际运行配置取得的城市/方向/工作类型/经验/启用薪资范围、本次上海日期。不能只传模型摘出的职责或要求，不能读取不存在的搜索计划字段而送空偏好。

输入来源索引复用现有 evidence catalog，给模型短编号；每项按精确路径或原句无损指回当前原材料。程序检查结构、来源身份及类型，不要求所有合理常态推断被一句原文逐字证明。来源绑定正确也不等于自然语言推理正确，效果验收仍需判读。

模型仅返回：

- `selectedWork`：所选实际主工作和 JD 来源编号。
- `supportingEvidenceRefs`：支持机会的候选来源编号，原句由程序展示。
- `materialConsiderations`：影响投入的真实支持、交付差距、条件或不确定性及来源。
- `modelRecommendation`：主投、可投、慎投、不推荐。
- `decisionExplanation`：自然中文的实用解释。

四档由模型综合判断，程序不再用 70/30 矩阵、普通资格 unknown 封顶或局部词规则重写。主投有强直接支持；可投有直接或有意义的迁移支持；慎投有实质差距但仍可推进；不推荐说明不同主工作或确实关闭的范围。

完整 JD、资料不足、范围排除、待刷新、模型失败分别保存。保留 `componentRecommendation`、前置原因、匹配状态和最终建议，避免把前筛排除说成模型工作不匹配。格式规范化只记录通用无意义空回显，不添事实、引文或推荐。

冻结消费器同时保留此前明确列出的三个运输/空回显例外：`type: "json_object"`、`contractRepair: null`、`decisionExplanationNote: ""`。只能删除这些精确值和六个已知输入数组的空回显，记录删除字段；非空值、不同值及任何其他未知字段仍失败。这是研究中已验证的结构规范化，不是新增语义推断或无限容错。

## 5. 有界恢复与隐私

每次匹配最多首次调用加一次恢复。结构/来源错误反馈全部独立错误及实际无效对象；坏 JSON 反馈该次实际原回复；截断在原材料不变下扩大既有预算。第二次失败保持失败，不再叠恢复，不删括号、不编造缺失字段、不挑选历史成功结果。

请求级预算/重试参数不能通过修改共享适配器属性实现，避免并发岗位串用设置。JSON 模式不支持时的协议兼容请求需单独计入真实 HTTP 次数，不能藏在“两次任务调用”内。中止、额度和认证错误继续走已有暂停/停止流程。

坏 JSON 原文仅作该请求内部恢复数据，不能落到公开错误、通用日志、Git 或页面。恢复反馈不能串到另一岗位；脱敏及简历版本/文件绑定继续生效。

## 6. 生产接入与旧数据

复用适配器、队列、缓存、存储和页面。`job_analysis` 对新模式直接请求完整工作判断；旧 split/legacy 保留为明确兼容/回退路径，新模式失败不静默回到旧矩阵。Mock 的规则演示仍不能冒充真实模型质量证据。

新分析保留完整五字段、支持原句、前置状态、最终建议和错误，同时映射现有 `roleSummary`、`fitReasons` 等展示字段。不伪造百分比分数、逐项能力状态或资格表。页面与消息用同一已保存结论；新结果不会显示成“历史分析待计算”或被旧 `jobQuality`/资格字段再次改档。

缓存使用新的任务/管道版本、完整输入哈希及实际模型推理配置。缓存读取重新核对来源；失败和资料不足不能缓存成成功。旧成功记录标需刷新，保留原 JSON，不重算或伪装成新语义。

完整简历修复仅涉及 `source.resumeEvidenceText`，其他短字段限制保留。历史非空 1000 字精确前缀也需要恢复；必须确认 profile version、确认卡、document 归属、文档哈希和脱敏成功。不能拿另一份新简历替换旧卡绑定的事实，不能覆盖用户修订。

## 7. 实施与验收入口

实施顺序和准确文件见同日 `jd-work-selection-implementation` 计划。先做能暴露缺陷的行为回归，再实现；保留现有账号、数据恢复和 JD 覆盖要求。结果保存/读取、页面分桶、默认勾选、消息上下文及重开都需验证。

定向回归通过后执行当前完整门禁、必需浏览器检查和正式复查；提交后重跑准确 SHA 并核对同 SHA CI。之后在隔离验收环境用明确开启思考配置、新空操作岗位基线和普通 Edge 验证。旧岗位库只作恢复证据，画像/简历/卡/计划/模型设置保留。

不发布、不代替人工最终验收；原四步和一周真实使用观察仍需回接。关闭思考配置当前未达到同样效果，最终体验配置及其差异必须明确，不把实验配置当现用户默认已改善。
