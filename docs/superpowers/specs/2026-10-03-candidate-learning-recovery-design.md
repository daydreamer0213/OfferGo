# 三模块资料更新与学习恢复设计

需求来自逐条核对已实现行为时确认的四个缺口。本轮修复连接与恢复，不扩建记忆系统。

## 面试

一轮训练选定的简历、岗位 JD 和历史问答作为固定依据。每次下一题、整轮复盘和重答反馈生成时，再读取当前有效的补充经历、事实与历史回答；重新构建包含补充资料的出题提纲，防止旧提纲保留已撤回信息。保存的历史上下文不重写。

同义条件问法覆盖“来上班”“开始工作”“报到”等常见到岗表达。纯条件登记触发现有一次定向重新生成；有实质能力或动机考察的混合问题仍允许。常见措辞和标点归一后重复的题目使用相同恢复路径；不靠关键词相同否定正常深入追问，不承诺穷尽全部语义重复。

## 回复与简历

消息发现和补充缺失事实共用已有回复资料入口，从现有简历版本存储读取最新启用正文并沿用身份遮盖规则。正文作为 currentResume.text 进入实际回复模型接口。模型优先使用当前正文而非旧画像的经历表述，当前求职条件以最新有效事实为准。不开启额外简历分析调用。

## 学习恢复

用户采用的回答和模型整理结果分别记录。整理失败或模型不可用时，原回答仍可被同范围的类似问题参考；页面只说明回答已保存。

学习状态使用现有 candidate_job_events 的 JSON 记录，按回答编号关联，不增加表或数据库版本。恢复读取原回答，只补做事实和经历整理；原确认时间决定事实先后，避免稍后恢复旧回答覆盖新手动资料。写入前再次核对回答未撤回且未被替代。成功状态和整理结果一起提交；重复/并发恢复复用同一任务，不再写入重复资料，不执行平台发送。

在现有沟通资料页面提供“补做资料整理”；模型就绪时访问此页也可以后台补做一次。没有常驻定时器、无限重试或全量阻塞。旧数据库没有学习状态的记录保留现有资料，不自动重做历史整理。

## 验证范围

回归检查实际应用调用参数、失败恢复写入及事务边界；Edge 检查页面按钮、提示与刷新后结果。完整离线门禁要求浏览器检查实际运行。本轮不发送消息、不扫描真实平台、不修改用户资料，不将离线模型场景当作真实平台验收。
