# 消息只读发现误判修复设计

## 问题与证据

2026-09-17 人工验收同时出现两个只读消息发现错误：

- 智联返回 `ZHAOPIN_MESSAGE_STRUCTURE_CHANGED`。实时 DOM 显示 `/im` 页面已经加载 19 条会话，左侧和主面板 Vue 组件均正常；页面处于尚未选择会话的合法空状态，因此没有聊天标题和消息节点。当前快照把“没有聊天标题”误判为结构变化。
- BOSS 返回 `BOSS_MESSAGE_DETAIL_BASELINE_NOT_RESTORED`。本次访问预算没有记录详情打开动作，说明错误发生在详情打开前的节奏等待阶段。实时 CDP 状态显示固定窗口处于 `minimized`，六个原有页面的 `document.visibilityState` 因此全部变为 hidden；固定标签页、窗口和 URL 均未丢失。当前基线把窗口最小化造成的可见性变化误判为标签页漂移。

## 目标行为

1. 智联消息页在会话列表加载完成但尚未选中会话时可以进入只读发现；选择目标会话后仍须严格验证会话 ID、岗位 ID、聊天标题和消息归属。
2. BOSS 专用 Edge 在只读等待期间被最小化时可以继续。最小化只能豁免由窗口状态导致的“一个可见页变成零个可见页”；固定 BOSS 标签页、窗口 ID、全部标签页集合、临时详情页数量和岗位身份仍须保持一致。
3. 未知新增标签页、固定标签页丢失、详情页前台打开、跨窗口创建、岗位不一致、登录或风控页面继续立即停止。
4. 诊断日志只记录阶段、差异种类、数量和窗口状态，不记录 URL 参数、岗位内容、会话内容或登录数据。

## 方案

### 智联列表与会话状态分离

`ZHAOPIN_MESSAGE_SNAPSHOT_EXPRESSION` 只要求左侧会话组件和主面板组件存在。聊天标题可在初始空状态缺失，返回空的活动会话字段。`scanConversationRows` 可以据此生成只读队列。`openQueuedConversation` 点击目标行后继续使用现有 `selectedIdentityMatches`，只有标题、活动会话和岗位身份完全一致才读取消息或岗位详情。

### BOSS 最小化状态可观察化

`CdpBrowserAdapter.listTabs` 为每个页面附带所在窗口的 `windowState`。详情读取基线保存固定窗口状态。比较可见页时，当前窗口为 `minimized` 才允许原可见页暂时变成不可观察；所有标签页身份、BOSS 固定页身份、窗口 ID 和额外页数量仍须一致。若任务从最小化状态开始，窗口后来恢复显示，则必须重新建立与基线一致的可见页，不能凭空猜测选中的标签页。这样只忽略操作系统造成的可见性缺失，不忽略真实标签页变化。

详情读取失败时记录脱敏的 `phase` 和 `baselineMismatch`。可用值限定为固定枚举，例如 `visible_tabs`、`all_tabs`、`boss_tabs`、`window`、`fixed_tabs`，避免把页面数据写入日志。

## 测试与验收

- 智联回归测试覆盖“19 条会话已加载、没有选中会话、没有标题和消息”，扫描必须成功；点击后身份验证仍必须通过才可返回消息。
- BOSS 回归测试覆盖正常窗口切换为最小化但标签页不变时基线通过；未知页、固定页变化、跨窗口和多可见页仍失败。
- 运行相关快速测试，再运行完整离线门禁。
- 使用现有专用 Edge 串行执行一次 BOSS 与智联只读消息发现；不发送消息、不申请岗位。
- 生成新的可点击验收目录，并确认启动入口直接打开 OfferGo。
