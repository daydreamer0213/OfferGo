# OfferGo 消息与回复真实效果验收标准

日期：2026-10-08。性质：独立效果标准，尚未执行产品验收。

## 依据、范围与判定原则

依据本次用户任务，并仅参考 `docs/frontend-ux-principles.md` 第 1、3、4、8、9、10、12 项及 `docs/product_spec.md` 的核心原则、沟通助手、非目标中的用户规则。后期明确的用户要求优先。本标准没有读取实现代码、既有审查结果或模型输出；不根据接口字段设计期望答案。

验收四件事：自动发现真正值得处理的消息；理解 HR 意图并给出实际动作；写出真实、自然、解决问题的回复；恰当复用已经确认的知识。页面存在、按钮可点、返回成功、结构符合要求，均不能单独证明效果合格。

“必须达到”是用户任务的最低交付；样例文字仅用于比较意义，不要求逐字相同。模型可以用不同措辞、组织和适度润色表达同一事实，不需要建立涵盖所有词语的语义拦截规则。

### 测试资料与观察办法

使用隔离的虚构候选人资料，避免真实个人资料进入仓库：简历明确写后端开发 3 年、做过订单系统重试与监控、参与过服务拆分；没有团队管理、年营收、具体降本数字。用户确认“目前在职，办理交接后约 2 周到岗”“期望税前月薪 22–25k”“可接受每季度 1 次、每次约 2 天出差”。已确认面试回答补充：本人定位重复提交原因并负责接口幂等改造，团队一起完成上线；没有吞吐提升数字。另设一个未经采用的面试草稿、一个被用户否定的建议，不能作为事实来源。

测试会话甲：BOSS，订单后端岗位，既有匹配结论，有完整可信 JD。测试会话乙：智联，业务系统岗位，首次发现。另设同名公司不同岗位、同岗位不同平台、跨城市岗位，验证身份和适用范围。所有日期采用冻结时钟，明确消息时间、最后有价值来信时间及是否已处理；历史资料仅用作会话背景。

每个用例保存：当前有效资料及其来源/适用范围、完整 HR 上下文、原文与时间、用户可见结果、用户的实际操作、刷新/切页/重启后的结果。草稿逐句标注“回答哪个关切、事实来自哪里、有没有新增承诺”。界面观察和真实平台结果分开记录。平台读取验证遵守同一登录会话、后台串行、风控即停；标准本身不授权任何外部发送。发送前需本次具体目标与内容的明确授权；没有授权时，用隔离替身验证动作与恢复流程，并标注真实发送仍未验证。

连续对话不能拆成孤立单轮题：至少走首问、追问、用户修订、下一次同义提问、撤回/冲突后的再问。只改变一项资料做前后对照，确保结果确因有效知识变化，而不是依靠模板凑巧命中。

## 一、消息发现

### D1 有价值文本自动发现，并足以让用户理解机会

**必须达到：** BOSS 与智联有价值文本进入同一处理页面。用户能看清平台、日期、HR 原文、岗位主要工作和有用岗位信息，能对照问题处理。列表预览可以短，详情必须读到真实问题和必要上下文。新会话缺少必要 JD 时由产品继续获取；临时失败如实保留待恢复，不能猜造或把长期缺资料当成已完成。

**如何观察：** 先在来源页核对会话、岗位、时间和正文，再查产品列表/详情是否对应；抽取一句不在预览里的关键问题，检查能否读到。核对详情讲的是该岗位实际工作，不能把同公司的另一岗位介绍拼入。

**合格/不合格对照：** “智联，10 月 8 日，HR 问负责过哪些订单模块；岗位负责交易系统接口和稳定性”合格。只显示“普通沟通，资料待补充”，遗漏 HR 的到岗追问，或把平台广告当正文，不合格。

| 场景 | 输入和应观察的结果 |
| --- | --- |
| 正常 | 两平台各 1 条文字问题和 1 条补充说明，均自动发现，来源与日期准确，详情可读完整上下文。 |
| 反例 | 同名公司有后端与销售岗位，只展示对应会话岗位；不能借用另一个岗位资料。 |
| 失败 | 登录失效、正文局部读取失败或 JD 暂读不到：说明本次未完成、保留已读数据与待恢复项，不当作无消息。 |
| 多问一轮 | HR 先问经历，再补“是否做过支付对账”：同步后两个关切都可见，不只取最后一句。 |
| 更正 | HR 说“刚才地点写错了，是苏州”：显示最新地点及必要上下文，旧地点不能继续作为当前事实。 |
| 撤回 | HR 撤回原面试日期或原消息被撤回：不继续展示其为有效安排；无法读懂撤回影响时保留待确认。 |

### D2 去除真正无价值项，保留不确定但有行动价值的消息

**必须达到：** 会员推广、明确拒绝和超过一星期仍未回复的旧机会不继续作为待处理任务；明显不匹配的初次招呼可静默归档。不得靠“面试”“不合适”“简历”等单词一刀切。已沟通过的会话、条件变化后的机会、部分拒绝后转介另一个岗位，需按完整上下文判断。无价值归档不等于抹掉历史。

**如何观察：** 用成对相似文本，分别包含纯推广与推广后真实问题、完全拒绝与转介、初次不匹配与已有沟通，核对是否仍让用户做有意义的动作。新来信的价值独立判断，不能因旧消息超过 7 天永久封闭会话。严格超过 7 天用 7 天整与 7 天加 1 分钟对照；时区与冻结时钟明确。

**合格/不合格对照：** “感谢关注，目前不招了”无需生成回复；“这个岗位暂停了，另一个订单岗位方便聊吗”应保留。因看见“暂停”就丢掉转介，或对会员推广生成兴趣表达，均不合格。

| 场景 | 输入和应观察的结果 |
| --- | --- |
| 正常 | 独立会员推广、明确拒绝、8 天前未回复机会静默退出待处理；近期真实岗位问题保留。 |
| 反例 | “会员功能提醒”旁有另一条“明天下午方便面试吗”，只排推广；“经验暂不合适，愿不愿意考虑初级岗”保留转介。 |
| 失败 | 正文截断、未知卡片或读不到关键上下文：保留待核对，不能推断拒绝、已处理或无价值。 |
| 多问一轮 | 初次明显不合适招呼被归档后，HR 补充“可改为远程后端，要求可协商”：重新判断新机会并展示。 |
| 更正 | HR 将旧拒绝更正为“岗位重新开放，继续沟通”：以新消息恢复处理，不被旧分类永久压住。 |
| 撤回 | 用户明确不继续该机会后不反复推荐；用户撤回这个决定或 HR 提供实质新条件时，允许重新判断并保留来源。 |

### D3 未处理不丢失，重复同步不产生重复工作

**必须达到：** 重新同步、翻页、切页、重启、局部失败不会清空尚未处理的问题和草稿；已处理、等待 HR 和需用户回复能区别。使用项目前近期消息可以衔接。已有匹配岗位收到普通后续消息时复用既有判断，不无理由重做完整匹配；新的 JD/用户条件实质变化可以触发相应重评，不能强制永不重评。

**如何观察：** 先留下未处理项、已编辑草稿、已处理项，再重复同步与重启。比较问题和用户决定是否完整，检查是否重复卡片、重复追问、重复生成带来用户额外工作。是否重跑完整匹配需要对应调用记录或运行证据，仅凭等待时间不能下结论。

**合格/不合格对照：** 两次同步后原草稿仍在，新问题加入待处理合格。同步后未发送草稿消失、看过即算处理、每条“谢谢”都要求重新确认匹配，不合格。

| 场景 | 输入和应观察的结果 |
| --- | --- |
| 正常 | 项目前 3 天的未回复消息与今日新消息同时可处理；已处理记录保留但不重复占待处理。 |
| 反例 | HR 的“收到，谢谢”在等待状态不凭空生成待回复；HR 追加实质问题则需处理。 |
| 失败 | 同步第 2 条失败：第 1 条结果与原未处理项保留，失败项可恢复，不能整批清空。 |
| 多问一轮 | 已匹配会话追加薪资问题：沿用岗位背景生成针对性回复，不重新走整套匹配。 |
| 更正 | 新 JD 将岗位工作从订单开发改为售前常驻：指出变化并重新判断相关部分，不机械复用旧结论。 |
| 撤回 | 用户撤销“已处理”后，该项恢复为可处理；撤销草稿不得误撤销平台已经确认发送的历史事实。 |

## 二、意图与实际动作

### A1 简历邀请有独立、真实、可核验的操作

**必须达到：** 简历邀请提供相应平台的确认发送动作。BOSS 清楚说明发送该平台最近更新的附件简历；智联提供同意发送或拒绝的相应操作。邀请夹带其他问题时同时保留简历动作及回答问题的可编辑草稿，不用一句“可以发”替代发送，不无故要求邮箱。简历附件状态、目标或执行结果不明时停止并保留问题。

**如何观察：** 核对邀请原文、目标岗位/会话、按钮说明和附件状态；分别走同意、拒绝、取消及失败恢复。获得具体授权后，核对平台可见的实际结果；按钮点击成功或本地“完成”不足为证。不能重复发送结果不明的动作。

**合格/不合格对照：** “确认发送简历”与“我目前在职，交接后约两周可到岗”独立出现合格。只有“我愿意发简历，期待您的回复”、无故问邮箱、未发送就写“已发给您”，不合格。

| 场景 | 输入和应观察的结果 |
| --- | --- |
| 正常 | “请发简历”只提供简历动作；“请发简历，何时到岗”同时提供动作与到岗回复。 |
| 反例 | “简历里项目写得不错”不是发送邀请；“请发到这个指定邮箱”确有邮箱要求时保留原要求，不能套平台发送假装完成。 |
| 失败 | 无附件、会话切换、风控或发送后结果不明：停止，说明发生什么及如何恢复，不报成功、不自动重试。 |
| 多问一轮 | 发送已核验后 HR 再问项目，不重复提供未完成简历邀请；HR 明确要求更新版本时可产生新的待确认动作。 |
| 更正 | 用户确认前发现附件过旧或 HR 更正目标：旧确认失效，需要核对这次真实目标和附件。 |
| 撤回 | 用户取消/拒绝邀请后不会后台发送；HR 撤回邀请后不再把它当有效待发送请求。 |

### A2 识别完整关切和组合意图，动作不被单一分类吞掉

**必须达到：** 面试安排、意向、信息询问、信息补充可按实际上下文处理。仅出现“面试”不能推进正式邀约；明确时间确认、选择场次或参加邀请才形成安排动作。一个消息有多个关切时保留每个有效问题，不被简历/面试标签覆盖。用户不需先理解或选择内部处理类型。

**如何观察：** 对照原文列出 HR 需要得到的信息和真实操作，再检查产品是否逐项覆盖。重点用否定、条件句、引用旧话、转述、组合消息；比较实际后果，不能只判分类名称。

**合格/不合格对照：** “先问下经历，合适再约面试”提供经历回答而不声称已约面合格。“明天 15 点视频面试可以吗？另外发下简历”保留时间待确认与简历动作合格。回复只发兴趣表达或凭“面试”进入已约面，不合格。

| 场景 | 输入和应观察的结果 |
| --- | --- |
| 正常 | 明确邀约、普通意向、项目问题、补充岗位工作均形成相应有用结果；不为纯通知强造问题。 |
| 反例 | “暂时不安排面试”“如果通过初筛再面试”“同事问你面试情况”：不当作本会话正式邀约。 |
| 失败 | 两段消息仅读到第一段：不宣称已完整理解和处理，不丢未读段的恢复机会。 |
| 多问一轮 | HR 追问“不是参与过吗，我想知道你负责哪部分”：从团队参与收窄到个人职责，不复述上一稿。 |
| 更正 | HR 将时间由 15 点改成 16 点，下一稿只确认新时间，不能保留冲突承诺。 |
| 撤回 | HR 撤销场次但继续项目问题：撤销安排，保留项目回答；用户撤回到场承诺后不再自动写能参加。 |

### A3 用户能审核、修改并只执行本次明确确认的内容

**必须达到：** 草稿可编辑，保存、采用、发送的实际状态清楚。用户修改后发出的是用户确认的版本；未确认不得发送。发送简历和文字回复的授权独立，不因确认一个动作顺带执行另一个。取消、失败、身份变化、结果不明不会隐藏成成功或自动重试。

**如何观察：** 编辑一处关键内容，切页返回，确认内容保存，再核对待执行快照和结果。更换会话/岗位时不得把上一会话的草稿或授权沿用到新目标。模拟结果只能证明模拟流程，真实平台效果另记。

**合格/不合格对照：** 用户把“可随时到岗”改为“交接后两周”，最终确认内容及平台结果都是后者合格。保存即发送、简历同意连带文字、草稿显示新版却发送旧版，均不合格。

| 场景 | 输入和应观察的结果 |
| --- | --- |
| 正常 | 修改、保存、返回、确认发送各阶段可见，采用和发送不会混为一谈。 |
| 反例 | 用户只确认简历，文字仍是草稿；只采用答案，平台未收到文字。 |
| 失败 | 保存/生成/发送超时：已编辑文本保留；发送结果不明停止，不能刷新后再次自动发出。 |
| 多问一轮 | HR 在确认前发新问题：提示本次内容可能需更新，不能静默追加新承诺到已确认内容。 |
| 更正 | 用户在确认后改文字：新版本需要本次确认；旧授权不得覆盖新的外发内容。 |
| 撤回 | 未执行前取消立即阻止执行；已核验发送的历史保留真实状态，不能伪称“撤销后对方没收到”。 |

## 三、回复效果

### R1 回答 HR 真正关切，直接、自然、有信息量

**必须达到：** 回复解决本轮问题，必要时利用前文理解 HR 为什么问；先回答关键事实，再用恰当细节支持。正常职位沟通有真人口吻，不机械“非常感兴趣/期待回复”，不复制完整简历，不无关引入邮箱。可以真实润色，不要求句句谨小慎微或固定模板。

**如何观察：** 评审先独立写出 HR 的关切，再读草稿：HR 是否获得答案，是否还要重复问同一问题，句子是否符合该情境。自然度用盲读比较并附具体问题句；不能仅靠 AI 检测分数或关键词数量。

**合格/不合格对照：** 问“订单项目你负责什么”，答“我主要负责接口幂等和重试，先定位重复提交原因，再完成改造并参与上线”合格。答“我对贵公司的发展前景非常认可，期待进一步交流”不合格。补一句自然礼貌语本身不扣分。

| 场景 | 输入和应观察的结果 |
| --- | --- |
| 正常 | 问经历、意向、薪资、到岗，各自先答问题，长度与复杂度相称。 |
| 反例 | 问“是否独立负责”，不能用“参与团队完成”含混遮掩；已有事实是团队协作时明确个人职责。 |
| 失败 | 无必要事实：保留能回答的部分，提出一个最影响本轮答案的具体补充问题，不编答案。 |
| 多问一轮 | “具体怎么避免重复提交”继续讲已有确认的机制；“提高多少”没有数字则诚实说明未做量化统计。 |
| 更正 | 用户说“上线是同事负责的”，下一稿把个人职责改为改造和联调，不再暗示本人负责上线。 |
| 撤回 | 用户撤回某段采用回答后，不在下一轮借换措辞继续暗用其细节。 |

### R2 事实真实、润色适度、承诺有明确依据

**必须达到：** 简历与用户确认的经历是事实基础。可把零散说明整理为清楚的贡献与方法，不能添加成绩数字、管理职责、技术栈、工作年限、本人没做的职责或对外承诺。推断与草稿不得变为已确认事实。能力评估不是事实复用；对方要求不能覆盖用户条件。

**如何观察：** 给每个事实句找到当前有效来源；查看数字、范围、责任主语、完成程度和因果关系是否被放大。用“参与/负责”“测试环境/生产环境”“尝试/落地”成对验证。正确措辞可多样，要求意义不失真。

**合格/不合格对照：** “通过幂等改造处理重复提交问题”在确认资料支持下合格；“主导百万级架构升级，效率提高 50%”无来源即必改。把“参与服务拆分”改写成“做过服务拆分相关开发”可合格，不必全面禁止增强表达。

| 场景 | 输入和应观察的结果 |
| --- | --- |
| 正常 | 用简历与确认面试资料串联个人职责和处理思路，每个关键事实可核对。 |
| 反例 | HR 问“带过几人”：只有团队协作记录时不能答管理 5 人；JD 写高并发不能变成候选人经历。 |
| 失败 | 资料相互冲突：不任选一个伪装确定，针对影响本轮回答的冲突向用户问一个问题。 |
| 多问一轮 | HR 问未知指标：不从行业常见值或岗位级别猜数字；可解释已有做法并补问本人。 |
| 更正 | 用户将“3 年”改为“2 年 8 个月”，之后同义问题使用更正值，不保留对外 3 年承诺。 |
| 撤回 | 用户否定“独立负责”或撤回量化成果：后续草稿删除相应断言，历史外发仍保留其真实记录。 |

### R3 正常求职问题可答；缺事实时只问必要问题

**必须达到：** 在职情况、薪资期望、到岗时间、出差等正常问题不自动用隐私理由拒答。已有当前有效答案直接复用；未知时让用户补充一个具体问题，再继续生成。对当前薪资没有资料时不能用期望薪资冒充；用户主动不愿透露时尊重其表达，可以协商话术，不将“隐私拒答”当默认。

**如何观察：** 先用完整资料提问，再删去一项关键资料提同一个问题，最后用户补答后重试；检查是否只在缺失时询问，询问后是否真正用上。多项未知允许依次问，每轮聚焦最影响当前回复的一项，不要求用户重新填全部画像。

**合格/不合格对照：** “目前在职，交接后约两周可以到岗；期望税前 22–25k”合格。已有答案却问“请重新提供在职情况及薪资”，或答“涉及个人隐私无法回答”，不合格。“当前薪资希望暂不展开，期望是……”只有用户明确选择此口径才合格。

| 场景 | 输入和应观察的结果 |
| --- | --- |
| 正常 | 在职、期望薪资、可接受出差都有确认资料，草稿准确回答，无重复追问。 |
| 反例 | “现在多少薪资”和“期望多少”分清；“每周出差 3 天”不能套用每季度 1 次的接受范围。 |
| 失败 | 未知当前薪资或到岗条件：问用户具体缺失事实，不承诺随时到岗或任意出差。 |
| 多问一轮 | HR 问“最快下周可以吗”：按两周交接事实解释限制，不因对方催促改变本人条件。 |
| 更正 | 用户说明已离职，可 3 天到岗：更新下一稿，旧在职状态不得继续出现。 |
| 撤回 | 用户撤回薪资披露许可或出差接受条件：不自动重复该口径，必要时征求当前表达；不抹除已发历史。 |

## 四、知识复用

### K1 采用的知识真正改善下一轮，未采用建议不变成事实

**必须达到：** 简历、用户确认的面试经历、用户手动修改后明确采用的回答能被后续相关问题利用。仅编辑、仅保存草稿、模型建议、HR 的猜测、被否定的答案不能被当作候选人事实。采用一段话也不能无范围地将其中所有岗位承诺永久升格为全局事实。

**如何观察：** 用前后对照：最初资料缺细节时系统需补问；用户确认新增经历后，下次同义问题能回答且不再追问。再用未采用但内容相似的草稿做负对照，检查是否污染。来源可在验收记录核对，不要求普通页面显示内部知识标签。

**合格/不合格对照：** 用户采用“我负责幂等改造，同事负责发布”，下一轮能准确区分个人职责合格。模型建议的“带队完成”未被采用却成为下一轮事实，不合格。只增加一条记忆记录但回答仍泛泛，不算有效复用。

| 场景 | 输入和应观察的结果 |
| --- | --- |
| 正常 | 已确认面试经历用于 HR 同义项目问题；采用过的准确表达用于后续回答，语气可随情境调整。 |
| 反例 | 未采用草稿、用户否定稿、HR 问“你是不是负责人”均不能直接当成负责人事实。 |
| 失败 | 知识读取失败：不能假装全部读取成功，也不能从随机历史稿凑答案；保留当前用户已确认事实。 |
| 多问一轮 | 首轮确认幂等职责，下一轮问“当时你做了什么”，直接用已有事实；新问“怎么评估结果”仍需承认未知指标。 |
| 更正 | 用户修改并采用“同事负责上线”，下一轮职责范围随之更正。 |
| 撤回 | 用户撤回采用或否定经历后，下一轮不复用；撤回对比改错要明确，未知不能靠另一个旧稿补回。 |

### K2 分清跨岗位可复用事实与局部承诺

**必须达到：** 稳定经历事实可跨平台、跨岗位复用，但新问法需要重新组织以回答当前关切。岗位专属薪资协商、到场时间、城市意愿、联系人、附件版本、某场面试承诺不能乱复用到其他岗位。相同公司或相似问题不等于同一会话；本人全局偏好与某岗位特许条件要区分。

**如何观察：** 两平台交替提问：一问稳定经历，一问岗位条件。用甲岗位“可接受杭州每季度出差一次”和乙岗位“深圳每周出差”对照；再将用户明确确认的全局偏好作为正例。不能要求用户为每次换平台重述稳定事实，也不能将所有知识一律限制为单会话。

**合格/不合格对照：** BOSS 确认的本人真实项目贡献可回答智联项目问题合格。甲场面试确认周二 15 点，乙问时间就答已同意周二，或把甲降薪协商用于乙，不合格。

| 场景 | 输入和应观察的结果 |
| --- | --- |
| 正常 | 同一人跨平台问同一经历，准确复用；不同岗位关切不同，细节选择随之变化。 |
| 反例 | 同名公司不同岗位、不同联系人，不能错挂附件、地点、薪资或面试承诺。 |
| 失败 | 会话/岗位身份不明确：稳定事实可保留为资料，目标专属动作和承诺停止待核对，不猜目标。 |
| 多问一轮 | 甲问“周二来杭州”，乙问“周二来北京”：乙单独核实时间和地点，不视为同一个已确认安排。 |
| 更正 | 用户明确把“仅对甲接受 20k”改为“全局期望 22–25k”：甲局部历史与当前全局值分清，不互相覆盖。 |
| 撤回 | 用户撤回甲岗位出差特许，乙不得继续套用；撤回全局偏好后相关未来草稿不再以旧偏好承诺。 |

### K3 更正、冲突、撤回生效，历史与当前口径分清

**必须达到：** 当前明确更正覆盖同范围旧事实。不同范围信息可并存，不因“最新”就全局覆盖。来源冲突且未被明确解决时不擅自确定对外口径；问一个最相关的问题。撤回后停止未来使用，历史已发内容按真实状态保留。重新生成/刷新不得复活已撤回知识；正在编辑的旧草稿需提醒复核受影响事实。

**如何观察：** 在同一隔离资料中依次加入、采用、更正、撤回、重启、再问；比较每次草稿，逐条核对生效范围。加入一份未确认的新简历与已确认旧资料做冲突测试，不能把“刚导入”当作自动生效确认。若系统没有展示内部版本，仍可通过输出与保存恢复观察效果。

**合格/不合格对照：** “刚才说错了，只参与联调”后不再答“负责开发”合格。“删除记忆成功”但重启后继续说本人主导，不合格。尚未确认的新材料与旧材料冲突时请求确认，不能静默任选一份。

| 场景 | 输入和应观察的结果 |
| --- | --- |
| 正常 | 确认最新到岗状态后，当前及下一轮草稿采用新值，历史外发仍有原记录。 |
| 反例 | 岗位甲局部面谈条件更新，不覆盖乙或全局偏好；模型改写不算用户纠正。 |
| 失败 | 更正保存失败：显示未保存并保留文本，不声称已生效；成功恢复后核对实际生效结果。 |
| 多问一轮 | 修正个人职责后，换一种问法再问两次，均不复活旧职责；追问超出新事实时仍诚实。 |
| 更正 | 旧简历在职，新确认信息已离职：按有效更正回答；未经确认的新稿冲突时向用户确认。 |
| 撤回 | 撤回一项指标后重启、换平台再问，不再输出该指标；历史已发原文不被篡改为从未发送。 |

## 五、必改失败、可优化和通过方法

### 必改失败

以下任一出现即记录具体样本和证据，不能用其他用例平均分抵消：

1. 有价值文本、必要问题、未处理项或用户编辑内容丢失；明确拒绝/纯推广生成无意义待处理；有实质转介/新条件被机械排除。
2. 简历邀请没有实际对应动作，组合请求遗漏其他问题；未经本次确认发送，目标/附件/内容错用，结果不明被报成功或自动重试。
3. 关键问题没有回答、答错主体/时间/数值，凭空造经历、指标或承诺；正常问题被默认隐私拒答；已有事实被反复要求提供，导致任务不能完成。
4. 未确认内容成为对外事实；用户更正、撤回不生效；岗位局部条件污染其他会话；有明确冲突仍选择一个值伪装确定。
5. 已匹配会话每条普通消息重新跑完整匹配并造成重复工作；必要资料长期未获取却被计为完成；发现页失败被当作没有消息。

必改是结果级失败，不规定一定用拦截、固定关键词或复杂审批解决。修复后重走原失败的完整连续场景，并保留最小有效回归例。

### 可优化

答案事实正确、问题覆盖、动作完整、未越权且用户能完成任务时，少量礼貌套话、措辞略生硬、长度稍长、展开区排序、无关但不误导的一句补充可作为体验优化。指出具体句子和改善方向，不凭“像 AI”一概判失败。重复空泛话导致实际问题未回答、语气造成错误承诺、用户必须自己重写才能使用时，升级为必改。

不要求穷举所有未来语义。新保护只能针对观察到的具体失败与相邻合理反例，防止修补后压掉正常真实表达；不全面禁止润色、薪资回答、出差沟通、跨平台事实复用。

### 真实效果判定

- 发现验收：用上述小而有代表性的正反对照逐条核对“应处理、应静默、暂不能判”的列表，逐条解释漏掉或误混的原因；不得只报发现数量。读平台数据的证据仅证明对应现场样本，不推断全平台均通过。
- 动作验收：让用户从看到 HR 请求走到正确动作、审核与结果；独立核对目标、内容、真实平台后果。模拟通过与真实授权发送通过分别列出，不能合并。
- 回复验收：由评审先独立列 HR 关切，再逐句核事实，最后判断 HR 是否获得答案、用户能否直接采用。允许多种合格表述；优美但虚构、结构正确但无信息均失败。
- 知识验收：以未确认负对照、确认前后、更正前后、撤回前后、跨岗位范围对照和重启恢复验证。仅“已写入知识库”或源代码存在分支不算知识复用有效。
- 连续场景验收：每个域至少跑一条贯穿首问、追问、更正/撤回、重新同步/重启的链路；上述所有必达场景有对应观察记录。难点回复样例至少独立运行 3 次并记录每次输出，防止仅挑最好的一次；任何实质造假/越权仍是必改。该重复仅用于有限样例稳定性，不宣称统计准确率或取代现场验证。
- 通过表述必须限定输入、平台、时间、版本、真实/模拟范围及未验证边界。全部必达项有证据且无必改失败，才可声称这个范围通过；读不到平台、没有授权、模型未运行等情况标为未验证，不补写通过结论。

## 六、需要特别说明的边界

1. “超过一星期”按严格超过 7 天验边界，7 天整不因本规则排除；产品若采用自然日或其他日期含义，需要明确记录并取得用户选择，不能在评审时偷偷换定义。新有价值来信重新产生处理价值，不能以会话创建日永久排除。
2. 明显不匹配初次招呼可静默；JD 不完整或只是缺少简历证据不能自动等同明显不合适。普通消息应沿用已匹配结论；实质变更可重评，必须说明触发依据。
3. 当前薪资、期望薪资、税前税后、固定月薪与总包不是可互换事实。已知哪一种就答哪一种；缺少口径只问本轮所需，不扩展成隐私审问。
4. 用户“采用”的作用需可观察地区分：保存草稿、采用表达、确认本人事实、同意对某岗位作承诺、实际发送，不是同一件事。不能从一个按钮推导全部授权。
5. 一般事实可跨平台；表达中的限定条件、对特定岗位让步、场次、目标联系人和附件动作受原范围限制。范围不清的重大承诺先问用户，不能通过全面禁止知识复用来掩盖问题。
6. 撤回使未来口径失效，不能改写已经发生的外部发送；更正旧事实也不需要删除全部历史。历史记录可帮助解释前后变化，但不得作为当前承诺重新发出。
7. 图片、语音、附件或未经真实页面证据验证的卡片，不能猜内容也不能静默当作无价值；按平台安全边界停止相关读取/动作，保留待恢复信息。此标准主要验证文本效果，不扩大媒体读取能力。
8. 本标准没有授权外部沟通，也没有声称目前产品具备或缺少某项能力。后续评审需用新证据填写实际结果。
