## 当前结论

本轮取得一份新的完整 BOSS JD，原生一次普通 Edge 分析失败：首次 4096、唯一内置恢复 8192 的响应均为 `length`，最终答案均为零，全部输出额度用于思考。实际完整简历 3035 字、JD 1148 字、系统提示和来源索引在两次请求间一致。操作库保留六份有效结果及一份失败记录，不宣称七份有效筛选，也不把失败解读为岗位不匹配。

候选只把 DeepSeek V4 开启思考时的截断恢复扩大到 16384，保持首次额度、完整材料、提示、思考强度、校验及两次请求界限。关闭思考和其他模型仍为 8192；认证、余额不足及 429 仍立即停止。最小实际 transport 检查在旧实现因 8192/16384 差异失败，候选修改后通过；相邻适配器检查通过。完整版本门禁、同 SHA CI 和候选采纳均未完成。

## 实际实验及限制

受控恢复只新增一次模型 HTTP：重用已捕获的首次截断响应，通过原生适配器发出第二次请求；除 max_tokens 外与原第二次发送完全一致。资料已经看过，这是诊断实验，不是新的独立质量样本，也不是再次提交原普通页面任务。原失败记录与操作库均未覆盖。

候选请求成功，生成符合现有结构及来源校验的答案，总输出 5397 tokens，其中思考 4569。由于 5397 仍小于旧额度 8192，本次只能确认可生成有效答案，不能确认扩大上限改善了容量或成功率；随机性是可能解释，尚未证实。候选保持实验状态，原失败和候选发送/响应单独保留，不为追求成功继续重放该例。

父任务逐条复查候选实际内容：认可企业 Agent/RAG 组件贡献和个人完整 Agent 交付，Java 经验不足如实表述，未因专业、全日制省略或隐藏学历制造前置阻断。可投与较低优先尝试均有现实判断空间，不用档位是否一致代替质量验收。仍有一项非决定性措辞局限：JD 允许 Function Call 或类似系统、同类 Agent 实践，答案仍将 MCP 和点名框架未展示列为技能覆盖缺口。本项不是盲评或独立人工验收，也不宣称所有解释已通过。
