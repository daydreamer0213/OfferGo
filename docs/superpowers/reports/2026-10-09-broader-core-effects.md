# 三个核心模块：新增背景与连续训练效果补验

接续[四步执行清单](../plans/2026-10-09-four-step-acceptance.md)的第 2 步。合成资料使用测试工程师与客户成功转客户运营两种职业背景；生成前保存效果期望。通过现有真实模型和生产应用服务执行，没有替换成固定成功的 mock 结果。

## 怎样才算有用

| 模块 | 这轮重点判断 |
| --- | --- |
| 回复 | 回答 HR 当前的问题，使用已有真实经历与安排；不编故障原因，不把被拒绝的时间再约一次，不追加无关的职责或指标声明。简历邀请由独立平台动作承接，文字只答剩下的问题。 |
| 面试 | 通用轮考查实际方法、协作、取舍、学习与方向；岗位轮结合 JD 考查培训、客户问题、分析与迁移。具体回答后能换主题，真正缺例子时能指出；整轮合看前后回答，不强行制造重答任务。 |
| 简历 | 原教育、工作、项目结构和单位日期保留；改写使具体工作更易读。定向版突出与 JD 相关的已有经历，不添自动化、SQL、增长等未具备的能力，不用“相关经历”标签破坏原结构。 |

## 实际做了什么

- 六类 HR 消息分别生成实际草稿，再对问题案例及反例复测：项目方法、自动化经历、培训效果、可用面试时间、改约、简历邀请附带在职问题。
- 两个背景各生成通用和岗位定向简历，共四份完整成稿，并通过生产服务启用。逐份阅读完整简历，不能只看模型调用或建议校验成功。
- 两个背景各连续回答六题并生成整轮复盘。测试工程师走通用轮，客户运营走所选岗位专项轮；原题、原答、逐题反馈和报告完整保留。
- 新增案例加入现有自然表达验收样本，不新建模型或第二套业务流程。私有模型设置只读，运行前后比较散列，确认未改动。

这些是实际模型和应用服务的效果实验，不能称作本轮所有内容已经在 Edge 操作完成，也不证明实际 HR 已收到回复或简历。

## 确认并修正的问题

| 原来会发生什么 | 修正与复测结果 |
| --- | --- |
| 测试经历只写了现象和复测，回复却补成已经诊断出状态同步故障。 | 区分观察现象与已确认原因；同例直接回答重复提交、记录参数与回归，已知根因的对照仍可自然说明。 |
| HR 拒绝周一 15 点、改约周二，用户周二不便，草稿又提出含周一 15 点的宽时段。 | 同时核对双方限制；实际回复改为周一 14 点或 16 点，开放时间对照仍可给 14—17 点。 |
| HR 问培训是否有效，草稿讲完操作检查又追加“未统计续费率”旁注。两轮均出现。 | 补实际自然表达示例；焦点复测只回答客户操作完成、卡点与说明调整。明确问指标的对照仍直接回答未统计，没有隐私拒答、虚构数字或无谓补问。 |
| 后题已经补清验证方法，整轮复盘仍要求重答前题补同样内容。 | 合看前后回答，并区分当前缺口与可深入追问。原六题输入复测得到切题认可、改进与重答为空；深入细节保留在可能追问中。 |
| 客户运营点评先表扬“守住边界、没有夸大”。 | 焦点复测改为认可模板、三行检查和培训说明调整，并明确指出原题还缺 Excel 汇总如何影响跟进的例子。 |
| 删除简历旁注后留下两个句号；初步修复还会误删相邻替换的首字。 | 渲染只清理新形成的重复句号，保护其他建议的原文范围。19 项效果回归通过；原始模型输出经过相同应用输入重新生成并启用，只有多余句号改变。独立复查两种建议顺序均正确。 |

客户运营的完整对照复盘仍指出第 2、3 题缺少具体历史案例，同时认可后题已补充培训实例。允许优秀回答没有重答任务，并没有抹去真正未回答的内容。生成成功之外，还逐条判断了实际文本是否符合以上标准。
