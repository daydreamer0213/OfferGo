# 原样保存方案导致有效推荐误过期

已在准确产品源码 `04a03b2f0e4616418a4a1c1b34dbaab491f52ee9` 的真实资料独立副本复现：普通 Edge 原样保存一次，9 份已完成分析全部被标成过期，唯一原因是模型版本变化；2 份旧失败保持。保存前的 9 份分析与当前实际模型、资料和方案版本相符，实际表单零字段改变，模型设置、画像、确认卡、完整简历、缓存和原资料副本未变。

根因是方案保存重算使用源码目录的静态模型配置，而实际筛选使用 Data 中的批量筛选配置。本例静态配置是离线模型，实际是已保存的 DeepSeek Flash。因此正常重存会让推荐退出有效池，并制造不必要的重新分析。

工作树修复复用现有运行时 `batch_screening` 模型函数与缓存，无活动任务才构建重算配置。有活动任务继续延期，保存仍不要求模型连接或可读凭据。没有修改岗位判断提示、投递档位、采集覆盖或风险策略。

新增现有模块内的原生保存/默认重算回归，先实际失败于“完整分析应保持完成”，修后通过；真实模型变化及确认资料变化仍失效、活动任务不额外解析模型、未提供可读凭据仍可本地保存。本例没有模拟损坏凭据，原凭据错误处理未改。工作树的今日页、Dashboard 模型缓存和模型缓存三项相关检查通过，独立窄复查未发现严重或重要阻断。修后普通 Edge 和准确新提交完整门禁/CI 仍待完成，旧 200 项结果不能继承为新版本通过。

首次工具错误来自 SQLite 记录对象形式与 JSON 对象的比较，发生在服务、浏览器和业务提交前。保留首失败，只修完整内容比较后在同一副本续接，实际保存合计仍为一次，没有重建数据。独立复核确认旧结果失效与配置来源不一致；页面上的预览 JSON 提示来自验收工具阻断平台 GET，不归因产品界面。
