# 第二套模拟用户：消息、面试与简历验收

## 验收对象与边界

2026-10-04，使用新的虚拟用户陈亦航：杭州求职、四年 Node.js 后端经验，参与订单、退款、支付回调和库存对账。总体方案由技术负责人确定；本人负责接口、事务处理、联调与证据整理，没有团队管理或独立架构经验，也没有可验证的性能提升比例。

在隔离 SQLite 数据库中启动实际 Dashboard，用本机 Edge 无界面浏览器执行真实页面表单、按钮、保存、导出和启用操作。岗位 JD 与匹配结论作为完整测试资料预置；本轮不评估首次简历解析或岗位匹配的准确率。

HR 消息与平台操作结果由模拟读取器、发送器提供，没有访问真实 BOSS／智联，也没有真实发送消息或简历。模型走项目 Agent stdio 接口，由当前 Agent 根据实际请求提供结果；相同消息案例的修复回放复用此前相同输入的 Agent 响应。本轮证明页面、编排、持久化及学习链路能够运行，不证明第三方模型表现或实时平台 DOM 兼容性。

## 19 类 HR 消息

| 场景 | 观察和预期结果 |
| --- | --- |
| BOSS 合适岗位打招呼 | 简短表达正在看机会，不生成长篇套话 |
| BOSS 纯简历邀请 | 提供发送简历按钮；完成后不再要求回复历史致谢稿 |

| 项目职责、设计与测试追问 | 区分技术负责人定方案与本人实现，按实际经历回答 |
| 在职与到岗时间 | 使用用户确认的情况，不以隐私理由拒答 |
| 期望薪资 | 根据已确认范围简短回复，不擅自接受低薪 |
| 出差与加班 | 表达短期出差和偶尔紧急故障可接受、长期驻场及大小周不接受 |
| 上午面试邀请 | 根据已确认的下午可用时间提出协调 |
| 改约明天下午三点 | 正常处理时间协调，不误判成拒绝 |
| 明确拒绝 | 结束处理，不生成挽留草稿 |
| 委婉拒绝 | 结束处理，不继续回答 |
| BOSS 会员推广 | 不进入用户消息列表 |
| 简历收件通知、等待技术负责人反馈 | 进入等待分组；致谢草稿默认收起，可选查看 |
| 十天前未回复的旧邀请 | 不进入当前待处理 |
| 明显不匹配的高级广告优化师打招呼 | 使用已有完整不匹配结论，静默排除 |
| 用户已回复、等待 HR | 保留等待状态，不生成新的回答 |
| 离职原因 | 先由用户补充真实原因，再生成自然回复 |
| 英语能力 | 区分读文档、日常交流和主持会议，不能夸大 |

初次缺少的个人事实通过页面补充，包括支付回调实现细节、薪资、出差、加班、面试时间、离职原因和英语能力。重复同步保留未解决的问题，没有新增草稿或再次调用模型。

## 三个模块的衔接

1. 用户编辑项目回复，说明本人负责 Node.js 接口与事务、交易号唯一约束、重复及并发联调，并保存／复制。项目收集并确认两条稳定经历；没有把复制当作已发送。
2. 通用面试完成三题：项目目标与分工、库存差异与运营协作、验证方式和反思。
3. 岗位面试完成三题：支付回调事务与唯一约束、并发通知验证、库存差异判断及跨团队处理。第三题区分做过的经历与假设情况下的做法。
4. 面试中补充“取消订单与库存补回不同步”的实际经历，用户通过页面确认保存。未来计划没有被保存成已发生的成果。
5. 生成通用简历与岗位定向简历，分别下载文字版、核对导出内容、启用为新版本；原始版本保留。两版都纳入确认后的库存差异经历；定向版突出订单、售后、支付回调和事务处理，没有虚构数字、技能或扩大职责。

## 验收发现并修复的问题

| 实际问题 | 用户受到的影响 | 修正 |
| --- | --- | --- |
| 所有非拒绝消息都进入待处理，包括纯收件通知 | 用户被要求回答无需回答的信息 | 狭窄识别纯收件等待通知；有实际问题或动作仍保留待办 |
| 重复读取已分类的消息直接结束收件项 | 尚未回复的问题会从待处理消失 | 保留同一最后消息的待处理／等待状态；按同组上下文恢复旧版误结束的未回复问题 |
| 简历操作成功结束整条会话 | 混合邀请里的问题被遗漏 | 仅在没有剩余问题时结束；缺资料、开放回答及待人工确认的问题仍保留 |
| 同组另一版草稿开放时，已发送答案可能重新成为待办 | 用户可能误以为没有发送，重复操作 | 以同组学习记录中的已发送事实或平台发送项成功为依据，不以备选稿开放推断未回复 |

同时修正已发送简历仍显示“索要简历”的标签，以及纯邀请完成后仍要求回复旧致谢稿的展示。没有修改平台选择器、访问间隔、发送授权、数据库结构或外部协议。
