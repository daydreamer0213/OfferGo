# 真实 Edge 消息同步验收

本轮从已发布 v1.4.1 的实际使用环境开始，点击页面按钮完成同步，随后用当前用户数据的隔离备份复测修复。没有向任何真实招聘方发送消息或简历。

## 确认并修复的问题

| 实际问题 | 用户会遇到什么 | 修复 |
| --- | --- | --- |
| Edge 已打开的消息页进入休眠后，不出现在 CDP 页面清单里 | 页面明明开着，OfferGo 却漏读 BOSS | 在指定工作区后台恢复原标签页；先确认页面身份，不新建替代页、不切换前台 |
| 一个启用平台未连接，另一个完成后整体仍报告完成 | 用户可能误以为两个平台都读过 | 整体保留未完成状态和原因；可用平台仍正常读取 |
| 招聘寒暄附带简历邀请被当成新的意向问题 | HR 让发简历，草稿却追问岗位工作内容 | 将纯邀请转为简短回应，保留同一条消息中的薪资、约面和项目问题 |
| BOSS 的显示时间紧贴“你好” | 时间戳使寒暄未被识别，多生成一段回复 | 只在判断纯寒暄时识别前面的显示时间，不删掉问题里的真实面试时间 |
| 升级后已经保存的错误草稿继续展示 | 新生成规则修好，旧结果仍然不好用 | 同步时修复未编辑的纯邀请草稿；复制过、用户编辑过、已确认待发送或已发送的草稿保持原样 |

## 实际复测结果

- 在现有 Edge 中将原 BOSS 消息标签页置于休眠，从 OfferGo 点击同步，软件自行恢复并读取。没有新增重复消息页，前台保持在 OfferGo。
- BOSS 读取到 25 条列表记录，智联读取到 20 条。这里是平台列表记录数，不代表有 45 条待回复消息。
- 本轮新发现 1 条 BOSS 简历请求，补齐岗位资料及分析后显示发送简历按钮；此前的 BOSS 和智联请求仍保留。
- 最终两平台均为 `completed`，未完成项为 0，行动收件箱共有 3 条邀请。
- 三条邀请的可见草稿均为“好的，您先看看。”；岗位介绍、薪资和地点在草稿之前，匹配分析默认收起。
- 再次同步没有新增重复消息或草稿，也没有重复分析已完成的岗位。
- 工作区的离线回归确认：原搜索页和消息页休眠时优先恢复，搜索条件保留，不创建重复页。
- 冻结本轮功能代码后，完整 195 项离线检查全部通过，强制执行了浏览器检查。隔离预览运行的 7 个修复源文件与被检查的工作区文件逐项哈希一致。

## 验收边界

这次确认的是实际平台读取、岗位资料与分析、邀请识别、草稿效果、数据复用和页面展示。真实消息发送及简历发送没有执行；不能把按钮出现算成外部发送已通过。软件通过离线发送回归检查，真实外部动作仍需要用户对具体目标与内容授权。

候选验收页为 `http://127.0.0.1:8793/messages?planId=1`，使用隔离数据备份。正式发布包和原验收数据未被覆盖。本轮没有发布新的版本号。

私有现场记录位于 D 盘 `OfferGo-validation/2026-10-09/real-message-journey-2026-10-09T09-48-39-672Z`，包含原数据备份、同步结果、页面截图和离线检查日志；未提交真实会话内容、账号资料、模型密钥或数据库到仓库。
