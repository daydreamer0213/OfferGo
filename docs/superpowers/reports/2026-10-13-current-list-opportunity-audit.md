## 投递判定

实际清单为六份慎投、两份不推荐、两份待分析。父任务和独立 Agent 按完整实际简历、JD、重要考虑和理由审查，未发现新的决定性误推荐或误排：

- 六份慎投均有实际 AI/Agent 或工程交付支持，同时各自主体职责仍有实质差距，适合少量尝试。车载 Agent、业务 Agent 和 AI 实施较值得了解；架构治理、跨境内容自动化和资深 Java 全栈各有不同缺口，不把标题相近视为同一工作。
- 硬件岗位的主要交付与已有软件 AI 工作不同；相关专业不能替代硬件交付经历。限定毕业届次的校招岗位与已列毕业及工作经历直接冲突，未猜测隐藏学历。
- 两份失败没有可审计的最终判断，继续待分析，不算能力拒绝或质量成功。

此前已记录的指标支持遗漏、个人完整交付概括过窄、将“了解架构”加重为设计职责、SFT 例子偏重及一处引用错误等解释局限继续保留。此次“没有新的决定性误排”不代表所有解释零问题，不重答或按轻微措辞补提示。

## 排序和普通页面

原生读取与普通 Edge 的六慎投、两不推荐、两待分析顺序一致，完整 JD、实际理由及重开一致。六慎投在各自平台清单可手选，默认勾选为空；勾选和取消后的计数正常。排除和失败项没有进入沟通候选，主投/可投页为空，没有人为抬高档位。

当前排序先使用人工状态和投递档位，同档继续参考薪资、工作节奏、辅助标签、活跃度与最近采集时间等；不以旧岗位 score 改写模型档位。独立审查提出的机会先后仅是内容建议，产品尚未实现同档内更细的语义能力排名，不能由队列顺序宣称这一部分已验收。

页面核验只在 D 盘独立副本执行本地 GET 和未提交的复选框操作，没有点击确认或执行。截图实际查看，BOSS 两慎投和未勾选状态可见；智联及全部全文/顺序由完整 DOM 和保存记录核对。临时页关闭并回到原 Codex，保留七个必要页。

检查器误用旧方案编号及假设两平台卡片都有隐藏岗位 ID 的首失败保留。真实当前方案和只读卡片结构核对后，只纠正检查器绑定，以实际岗位链接、标题及完整正文共同核对身份，未重插岗位或调用模型。原操作库 57 表、简历/模型三文件和 8 有效 + 2 失败保持。
