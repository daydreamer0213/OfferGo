# OfferGo 用户体验审查：实际操作与内容取舍

日期：2026-10-04。审查代码：`192ce7896dcce2d2e91337be9b46320d0da20ab3`。

这是本轮工作的第二部分：在[用户提出的前端原则](../../frontend-ux-principles.md)之外，实际操作页面，检查任务是否顺畅、内容是否有用、下一步是否自然。本轮没有修改产品代码。

后续修复已在用户授权后实施，见[修复与复验记录](2026-10-04-ux-fix-verification.md)。本报告保留审查时的现象与证据，不用修后状态覆盖原始发现。

## 结论

发现四项已经复现、应修复的缺陷：简历编辑丢失、面试深色模式文字难读、消息详情漏掉已保存的工作地点、简历版本页面高亮错误导航。另有两类明确的体验缺口：启用后的简历缺少方便的继续编辑入口，正常任务区仍混入内部术语和开发阶段说明。等待提示可以进一步改善，但本轮没有证明正式环境生成卡死。

这不是“整套验收通过”。本轮把操作证据和代码原因核对到一起，先确定哪些问题值得修，避免因模拟资料或审美判断而误改功能。

## 怎么模拟用户

使用虚构用户陈亦航：杭州、四年 Node.js 后端经历，做过订单与退款接口、支付回调和库存核查；参与实现与测试，不虚构独立架构或带队经历。

用户的任务是：看懂 HR 的问题和岗位；生成并修改一份可用简历；练习项目面试题；离开页面以后还能继续；启用简历后还能进行小修改。

隔离环境使用以前模拟验收数据的数据库副本，并另外创建空数据库观察首次使用入口。所有数据库、浏览器证据和测试脚本在 D 盘。没有读取或修改真实用户数据库，没有联系 HR，也没有访问真实 BOSS 或智联。外部动作使用模拟实现。

页面主要通过本机已安装的 Edge 自动化复现，同时在 Codex 内置浏览器中人工式点击、输入和查看页面。当前 Edge 扩展连接不可用，因此这不是控制用户已经登录的 Edge 标签页进行平台验收。

本轮重新生成了一份完整通用简历，启动了一轮新的通用面试，并检查尚未提交的回答切页后恢复；也查看已有的完整面试复盘，并进入重练。模型请求由当前外层 Agent 回答，不涉及新的 API Key。这些步骤验证了当前界面的操作与呈现，不能代替不同模型、不同职业的内容质量评价。

## 已复现的问题

### 1. 简历改完立即切页，最后的修改会丢失

**用户想做什么：** 修改完简历，顺手去面试训练看一眼，然后回来继续。

**实际发生什么：** 两次修改后立即点击侧栏，返回后修改均消失；等到“已自动保存”后再切页，修改能保留。模拟保存接口失败后，页面虽显示错误，仍允许直接切走，返回后内容同样丢失。

**影响：** 用户以为自动保存会保护自己的编辑，实际需要记住等待或手动保存。网络或保存失败时，这个问题尤其容易发生。它影响用户输入，不只是提示文字问题。

**原因核对：** [简历页面脚本](../../../src/dashboard/pages/resume_optimization.js)在输入后延迟 600 毫秒保存；表单提交会等待保存，但侧栏离开、刷新等没有相应的未保存内容处理。已有消息页面会在切换前处理草稿，面试页面也已有本地回答恢复机制，可参考现有做法。

**建议：** 站内离开前完成最新保存；保存失败时保留文字并给出重试路径。刷新、关闭后能够恢复尚未保存的文本。正常成功路径不新增每次都要用户确认的弹窗。

**是否必要：** 必须修。优先于外观调整。

**证据：** `interaction-results.json` 中两次立即离开均为 `retained: false`，等待保存后的对照为 `true`；保存失败离开后为 `false`。截图、页面文本和复现脚本在下方证据目录。

### 2. 深色模式下，面试标题和复盘结论难以阅读

**用户想做什么：** 开启深色模式，阅读当前题目所属训练及训练结束后的结论。

**实际发生什么：** 训练标题和复盘结论使用很浅的背景，文字仍是白色，内容明显难读。训练中与已完成的页面均观察到问题。

**影响：** 用户看不清自己正在练什么，也难以阅读最重要的复盘结论。

**原因核对：** [主题变量](../../../src/dashboard/assets/theme.css)在深色模式下将 `--rf-ink` 用作浅色文字；[面试样式](../../../src/dashboard/assets/roleflow.css)又将它用于标题和结论背景，同时保留白字。简历结论有专门的深色背景覆盖，面试对应区块没有。

**建议：** 为这两个区块设置适合深色模式的背景和文字组合，保留现有界面方向；检查训练中、复盘、浅色模式。无需重做整套主题。

**是否必要：** 必须修。属于内容可读性，不是单纯的配色喜好。

**证据：** `verified-interview-dark.png`、`13-interview-dark.png`。标题实际文字为 `rgb(255,255,255)`，背景为 `rgb(237,245,240)`；简历结论的对照背景正常，没有把全部深色页面都判为失败。

### 3. 消息详情没有展示已经保存的工作地点

**用户想做什么：** 判断一个机会是否值得回应，先看看做什么、工资和工作地点。

**实际发生什么：** 测试岗位在数据库里有“杭州”，消息详情却没有展示。薪资能正常显示。

**影响：** 地点是求职的重要条件。用户不应为了获得本来已有的信息，再回平台或其他页面查询。

**原因核对：** [岗位信息投影](../../../src/core/message_discovery.js)没有向消息结果传递 `location`；[消息结果整理](../../../src/dashboard/message_discovery_controller.js)也没有保留它。[展示组件](../../../src/dashboard/message_presenter.js)已经支持“地点”，因此是信息传递缺口，不必另做一套岗位展示或调用模型补写。

**建议：** 将实际保存的地点沿现有消息数据链路传到展示组件，兼顾已有消息结果的读取。不从岗位名称或模型猜测地点。

**是否必要：** 必须修。

**证据：** `detail-results.json`：保存地点为“杭州”，消息详情未显示；`01-messages.txt`及页面截图。

### 4. 简历版本页高亮“今日任务”

**用户想做什么：** 在简历工作室查看已启用版本，再点击“查看全部简历版本”。

**实际发生什么：** URL 已进入 `/resumes?profileId=1`，标题为“简历版本”，侧栏当前项却变成“今日任务”。

**影响：** 用户切换相关页面后定位感中断，容易以为自己跳到了另一个功能。这属于真实导航不一致。

**原因核对：** [简历版本页面](../../../src/dashboard/server.js)向公共外壳传入的是今日任务地址 `currentPath: planPath`；[公共导航](../../../src/dashboard/ui/navigation.js)本身已支持简历路由。

**建议：** 修正当前页面地址，复用原有导航规则，无需再建立一套侧栏。

**是否必要：** 应修，改动范围小。

**证据：** `version-path-results.json`、`version-path.png`。

## 操作虽能完成，但不够自然的地方

以下是根据实际操作作出的体验判断。与前面的功能缺陷分开记录，不将所有不喜欢的文字都视为系统故障。

### 5. 启用简历后，想再改几个字，流程不顺

启用后全文成为只读，但它仍呈现为与编辑阶段很相似的文本框。页面提供复制和导出，历史版本管理主要能改版本设置；没有直接以当前全文继续编辑的入口。“生成另一个版本”则需要重新生成，无法顺手修改当前文字。

用户可能已经满意，只想改一个错字或补一句经历，却需要绕回复制、上传或再次生成。启用版本保留原样有合理用途，不应为了便利直接改写旧版本。

建议提供“以此版本继续编辑”：复制现有全文形成可编辑草稿，原版本保留，不必重新调用模型；同时清楚标明当前正在查看的是已启用版本。这是补齐编辑流程，不是解除数据保护。实施前核对已有草稿创建与保存能力，复用它们。

证据：`version-path-results.json`中的 `readOnly: true`、页面按钮，以及实际“启用版本 → 全部版本”的页面路径。

### 6. 普通页面仍让用户理解内部概念

| 实际出现的内容 | 为什么影响体验 | 调整方向 |
| --- | --- | --- |
| “阶段三 · 本地材料优化”“阶段四 · 简历通用训练优先” | 开发阶段不是用户需要的步骤，还容易让人误以为必须先完成阶段一、二 | 直接说明此页能做的事 |
| “冻结岗位”“冻结简历” | 用户需要知道本轮参考哪份资料，不需要学习“冻结”这个实现术语 | 改为“本轮参考岗位”“本轮参考简历”；保留本轮资料固定的实际行为 |
| “修改后会在 600 毫秒内自动保存” | 用户关心修改是否已经保存，具体延迟既无用，当前又容易产生保证保存的误解 | 简洁展示“未保存／正在保存／已保存／保存失败”的真实状态 |
| 岗位页面中的“待语义分析”“主扫描批次”，以及调整矩阵、权重、提示词必须确认的开发说明 | 用户只是查看岗位，却被迫了解分析和调参过程 | 对用户有价值的进度用普通话表达；内部标识与开发说明移到诊断或移除正常任务区的重复展示 |
| 沟通准备中的风险额度、技术性预留计数等 | 把内部访问预算解释成用户必须决策的参数，分散准备沟通清单的注意力 | 保留真实限制，正常页只说明本次可以处理多少及何时可继续；详细预算放诊断 |

还观察到页尾多处重复声明本地读写、不访问、不投递等。必要的发送确认及实际失败说明应保留，但不需要每个成长页面反复叠加一长串与当前任务无关的声明。

应按用户任务逐页取舍，不能简单删除所有状态，也不能只把术语换成中文后继续堆字段。消息来源、日期、保存状态、发送结果是用户需要的信息，应保留。明显调整布局时，先给具体预览，再落实。

证据：`04-resume.txt`、`13-interview-dark.txt`、`09-jobs.txt`、`11-communication.txt`及对应截图。

### 7. 生成等待提示还可以更具体

生成新简历和新训练时，按钮统一显示“处理中…”。它有禁用反馈，但没有很好地区分“正在整理简历”与“正在准备第一道题”。

建议使用对应任务的提示，失败后说明能否重试、资料是否保留；不增加虚假的完成百分比。本轮人为等待 Agent 返回数据，不能据此判定正式生成很慢或卡死。因此这是优化建议，不是已经复现的性能故障。

## 本轮实际没发现问题的范围

- 从现有简历生成完整通用草稿后，全文可查看、修改，修改说明可以对照原文；没有把优化结果仅做成一张建议清单。
- 等待“已自动保存”后切页再返回，简历编辑能保留。保存功能本身可用，问题在离开前的未完成保存。
- 新面试直接从项目经历提问，没有把到岗时间当作本轮第一道能力题。尚未提交的回答离开后能恢复；已有题目的重练输入离开后也能恢复。
- 已完成训练能够查看逐题记录，并从复盘进入具体题目的重练。
- 被检查的正常主页面保持公共侧栏；问题集中在简历版本页的当前项标识，而非整套侧栏消失。
- 检查的桌面与 640 像素窄窗口页面没有整体横向溢出；窄窗口消息能从列表进入详情。
- 检查页面没有记录到未捕获的浏览器页面异常，也没有发生外部平台请求。它们不代表上述体验缺陷不存在。

## 排除的误判与未验证范围

1. **测试岗位的职责介绍偏短：不列为正式产品缺陷。** 模拟分析使用了 `roleTasks` 等结果字段，当前正式投影却从 `responsibilityEvidence` 等分析字段构建内容。此次资料不等价于正式完整分析；需用符合生产结构的资料另测，不能为了旧模拟资料改生产逻辑。
2. **测试中的工作区无法读取平台筛选：不是本轮发现的真实平台故障。** 浏览器读取器被隔离替代，没有真实登录页。
3. **一次截图等待超时：不是页面卡死证据。** 面试页实际能在内置浏览器操作，后续 Edge 深色截图也完成。自动脚本中该次截图未完成，已保留失败记录。
4. **没有评价真实 API 模型响应速度。** 设置使用隔离运行依赖；导航耗时不能代表用户联网配置模型后的速度。
5. **没有重新验证真实平台同步、发送简历、发送文字或软件启动器。** 本轮着重用户操作与页面呈现；此前测试通过不作为这些范围当前通过的证明。
6. **新的三题训练只走到首题与回答恢复，没有再次完成整轮。** 完整复盘和重练用已有模拟记录检查，不混称为本轮新建训练完整通过。
7. **空数据库只观察了首次入口、设置与简历空状态。** 没有以新账号完整跑完首次下载到真实找岗的流程。

## 整改与复验顺序

1. 先保护简历编辑，复验立即切页、正常保存、保存失败、刷新恢复和启用前保存。
2. 修面试深色可读性，检查训练中、结束复盘、浅色模式及简历页面不受影响。
3. 补消息工作地点和简历版本导航，核对数据库中的地点与最终界面一致。
4. 补已启用简历继续编辑的自然入口；整理三个模块首屏内容和文字。明显布局变化先出预览。
5. 重走“看消息 → 修改回复 → 查看/编辑简历 → 练面试 → 回到消息”的受影响路径；关注信息是否保留、内容是否有用、用户是否要猜下一步。只在相关验证完成后说修复通过。
