## 这次怎样检查

## 已确认的问题及修改

| 问题及影响 | 根因与最小修改 | 复验依据 |
| --- | --- | --- |
| HR 问什么时候方便面试，项目在没有用户安排时说“时间比较灵活”，不能真正完成约面 | 区分 HR 提出具体场次与询问用户可用时间。未知/过期先问用户，已有有效时间直接回答，改场次重新确认 | `reply-baseline.json` → `reply-after-1.json`，九种情境逐句核对 |
| HR 同时约面、问项目、索要简历，有有效草稿却被判问题没答完 | 平台简历动作与文字问题覆盖分开。简历继续由原操作按钮处理，不凭文字声称已发送 | 同输入 `reply-mixed-after.json`，时间与个人职责都回答 |
| 面试题要求从前端“或”云环境举例，回答前端仍被要求补云环境 | 即时反馈、复盘和重答均按真实必答范围评价，深入选择的案例 | 原题原答案的新生成 `interview-exact-current.json`；不同题的新轮不冒充同题复验 |
| 泛问接口问题时，SQL 定位与验证被错当离题 | 接口慢查询属于接口问题；明确问参数/状态题时仍检查该特定内容 | `interview-after-1.json` 同时保留通用正例和专项反例 |
| 复盘文字显示为 `[object Object]`，用户看不到优缺点 | 保留实际对象中的文本和有效题号，继续支持既有字符串数组；提示声明正确返回格式 | 真实旧输出重放及最小回归；不据重放证明旧文案观点正确 |
| 正常简历重排后不能启用，日期下一行“个人”被当成新增数量业绩 | 数量匹配不跨行，其他真实数量与无依据数字校验保持 | LF/CRLF、200 个客户反例、真实后端原输出启用重放 |
| 简历建议的换行变成字面 `\n`，整段挤在一行 | 没有技术转义示例的输入才转换建议中的格式换行；已有真实 `\n` 示例保留 | `resume-good-replay.json` 原输出经当前服务，另有新生成对照 |
| 重新同步已经运行，页面仍显示上次“模型暂不可用” | 当前运行只显示当前进度；停止后的真实失败说明仍保留 | Edge 实际出现，页面正反回归先失败再通过 |
| 用户填了面试日期，正确草稿仍不能保存 | 时长检查误将“10月9日”当成工作时长；排除连续年月日的日期形式，真实 2 年/3 年经验仍核对 | Edge 实际补资料失败、同草稿复现、日期正例和改年限反例 |

独立复核还指出：题目让“挑一个例子”，复盘提纲又列出所有可选例子逐项补齐。已把提纲同样限定为选中案例，原报告输入新生成复验单独记录；不能只修即时反馈。
