# OfferGo 产品模块流程图

本报告按当前产品侧栏的 11 个模块，加上首次使用入口整理。箭头表示系统实际会走的分支；“确认”指用户对具体内容的操作授权。平台消息和岗位读取是只读操作，投递、打招呼、发送简历及回复都属于外部操作，需要各自的明确确认。

## 1. 首次使用：建立求职方向

```mermaid
flowchart TD
  A[导入简历] --> B{文件可读取吗}
  B -- 否 --> B1[说明文件问题，保留重试入口]
  B -- 是 --> C[解析经历、技能和求职意向]
  C --> D{画像与匹配卡已确认吗}
  D -- 否 --> E[展示画像和岗位匹配依据，等待修改或确认]
  E --> D
  D -- 是 --> F[生成并保存搜索方案]
  F --> G[进入今日任务]
  H[Agent 无界面入口] --> I{简历内容变了吗}
  I -- 没变 --> J[复用画像、匹配卡和方案；新操作保留新编号]
  I -- 变了或明确刷新 --> C
  J --> K[确认匹配卡后继续命令行流程]
```

首次使用建立的画像和搜索方案是后续筛选的依据。Agent 运行项目走命令行，不需要打开页面；相同简历的新一轮使用可继续求职流程，而不必重做画像。

## 2. 今日任务

```mermaid
flowchart TD
  A[打开今日任务] --> B[读取当前方案、浏览器与模型状态、已有工作]
  B --> C{是否需要调整搜索条件}
  C -- 是 --> D[修改并保存方案]
  C -- 否 --> E[选择 BOSS、智联或双平台]
  D --> E
  E --> F{运行条件是否就绪}
  F -- 否 --> G[显示具体待处理原因和恢复入口]
  F -- 是 --> H[启动本轮发现岗位]
  H --> I[查看本轮进度与待处理结果]
  I --> J[进入岗位记录、消息与回复或求职体检]
```

## 3. 发现岗位

```mermaid
flowchart TD
  A[选择平台并启动] --> B{单平台还是双平台}
  B -- 单平台 --> C[运行该平台原有扫描流程]
  B -- 双平台 --> D[BOSS 与智联各运行原有流程]
  C --> E[按平台节奏读取岗位卡与详情]
  D --> E
  E --> F{遇到登录、风控、页面丢失或停用吗}
  F -- 是 --> G[停止受影响流程，保存进度供恢复]
  F -- 否 --> H[本地去重、硬条件筛查、读取完整岗位信息]
  H --> I{资料足够分析吗}
  I -- 否 --> J[保留待补全或待重试，不给出确定推荐]
  I -- 是 --> K[结合简历生成匹配结论]
  K --> L[保存岗位与分析，进入岗位记录]
  G --> M[用户可暂停、停止或继续本轮]
  J --> M
```

双平台只是并行调度两个已有平台流程；每个平台内部依然按自己的节奏顺序读取，不同时打开多个岗位详情。

## 4. 岗位记录

```mermaid
flowchart TD
  A[打开岗位记录] --> B[选择平台、批次和筛选条件]
  B --> C[展示岗位来源、职责、分析与处理状态]
  C --> D{匹配结论如何}
  D -- 值得投或可投 --> E[查看详情、加入沟通清单]
  D -- 慎投 --> F[查看疑点，由用户决定是否保留]
  D -- 明确不合适 --> G[放在不推荐范围，不进入推荐清单]
  D -- 信息或分析未完成 --> H[补读详情或重试分析]
  E --> I[可记录处理结果和反馈]
  F --> I
  I --> J[供求职体检回看]
```

## 5. 求职体检

```mermaid
flowchart TD
  A[打开求职体检] --> B[读取扫描、岗位、沟通和来信记录]
  B --> C[按 BOSS 与智联分别统计]
  C --> D{样本和观察时间够吗}
  D -- 不够 --> E[展示已有事实，暂不下强结论]
  D -- 足够 --> F[比较发现、联系、回复和后续推进]
  F --> G[展示可能的卡点及策略建议]
  G --> H{用户选择调整搜索策略吗}
  H -- 是 --> I[记录新策略轮次，再观察新数据]
  H -- 否 --> J[继续当前策略并积累反馈]
```

这里的“体检”依赖真实记录；未发生的投递、面试或录用结果不能凭空推断。

## 6. 消息与回复

```mermaid
flowchart TD
  A[用户同步最新消息] --> B[按平台逐一刷新并只读扫描消息页]
  B --> C{登录、风控、页面身份或结构异常吗}
  C -- 是 --> C1[停止受影响读取，保存待重试进度]
  C -- 否 --> D[保存消息时间线，找出新来信和旧待办]
  D --> E{消息性质}
  E -- 会员推广等平台噪声 --> E1[过滤，不列为用户待办]
  E -- 自己最后发出 --> E2[显示等待对方]
  E -- HR 明确拒绝 --> E3[结束这条机会，不生成回复]
  E -- HR 新消息或打招呼 --> F[核对会话与岗位身份，复用或补读岗位详情]
  F --> G{岗位资料与匹配分析可靠完成吗}
  G -- 否 --> G1[保留读取进度并重试；不猜测岗位结论]
  G -- 是 --> H{岗位明确不合适吗}
  H -- 是 --> H1[静默移出待办，关闭旧草稿，保留历史]
  H -- 否，含慎投 --> I[识别 HR 的具体意图]
  I --> J{需要哪种操作}
  J -- 发简历 --> J1[展示发送简历确认]
  J -- 回答问题或约时间 --> J2[生成可修改的自然回复草稿]
  J -- 两者都要 --> J3[同时展示发送简历确认和回复草稿]
  J -- 缺少用户事实 --> J4[向用户询问必要事实，再准备回复]
  J1 --> K[用户确认具体动作]
  J2 --> K
  J3 --> K
  J4 --> K
  K --> L[执行前重新核对平台、会话、岗位和内容]
  L --> M{结果可明确确认吗}
  M -- 是 --> N[记录已执行结果，更新沟通进度]
  M -- 否 --> O[停止该操作，保留不确定状态，不自动重发]
```

“打过招呼”只说明产生了会话，不代表岗位适合。当前新增的匹配门槛只静默过滤分析已完成且明确不推荐、存在硬性冲突的岗位；慎投和信息不足不会被误判为不合适。历史消息仍保留在本地记录中，但不合适岗位不再占用待处理列表，旧回复草稿也禁止发送。

## 7. 沟通清单与记录

```mermaid
flowchart TD
  A[从岗位记录挑选机会] --> B[生成沟通清单和待发送内容]
  B --> C[用户逐项查看岗位来源、对象和文案]
  C --> D{确认了具体批次吗}
  D -- 否 --> E[只保留草稿和清单，不访问平台发送入口]
  D -- 是 --> F[冻结本批选择与内容]
  F --> G[逐项核对浏览器、岗位和招聘方身份]
  G --> H{身份与页面仍一致吗}
  H -- 否 --> I[停止并显示原因，保留未执行项]
  H -- 是 --> J[执行单项平台操作并核对结果]
  J --> K{结果明确吗}
  K -- 是 --> L[记录已联系或已发送，继续下一项]
  K -- 不明确 --> M[立即中断，不自动重复发送]
  L --> N[清单、记录和求职进度更新]
```

## 8. 简历工作室

```mermaid
flowchart TD
  A[选择现有简历与优化目标] --> B{通用优化还是参考具体岗位}
  B -- 具体岗位 --> C{岗位详情完整吗}
  C -- 否 --> D[先补齐岗位资料]
  C -- 是 --> E[结合岗位要求与简历现有证据]
  B -- 通用优化 --> F[结合现有简历和求职反馈]
  E --> G[生成修改建议与新草稿]
  F --> G
  G --> H[用户检查、编辑并保存]
  H --> I{内容是否有证据且通过完整性检查}
  I -- 否 --> J[指出需修正位置，不激活]
  I -- 是 --> K[用户激活新简历版本]
  K --> L[后续分析和面试训练可使用该版本]
```

## 9. 面试训练

```mermaid
flowchart TD
  A[选择通用练习或指定岗位] --> B{指定岗位资料完整吗}
  B -- 否 --> C[先补齐岗位信息]
  B -- 是或通用 --> D[结合简历版本生成问题]
  D --> E[用户逐题回答]
  E --> F[保存回答并给出反馈]
  F --> G{还有问题吗}
  G -- 有 --> E
  G -- 没有 --> H[生成训练报告]
  H --> I{想重答某题吗}
  I -- 是 --> J[重答并更新对应反馈]
  I -- 否 --> K[保留训练历史]
```

## 10. 招聘平台

```mermaid
flowchart TD
  A[打开招聘平台设置] --> B[查看 BOSS 与智联启用状态]
  B --> C[选择要启用的平台并保存]
  C --> D[检查当前浏览器工作区]
  D --> E{登录页和固定标签可用吗}
  E -- 否 --> F[提示登录或恢复工作区]
  E -- 是 --> G[平台可供今日任务和消息读取使用]
  G --> H[实际访问仍须遵守各平台独立节奏]
```

## 11. 模型与设置

```mermaid
flowchart TD
  A[打开模型与设置] --> B[查看普通用户的模型配置]
  B --> C{要修改配置吗}
  C -- 否 --> D[保留现有配置]
  C -- 是 --> E[输入模型接口与密钥，测试连接并保存]
  E --> F{模型可用吗}
  F -- 否 --> G[显示错误，依赖模型的分析暂缓]
  F -- 是 --> H[画像、岗位分析、草稿和训练可使用模型]
  I[Agent 运行项目] --> J[由外部 Agent 响应标准输入输出请求]
  J --> K[不需要在此页填写密钥]
```

## 12. 运行诊断

```mermaid
flowchart TD
  A[打开运行诊断] --> B[显示近期脱敏事件和当前状态]
  B --> C{正在定位问题吗}
  C -- 是 --> D[优先看警告与错误，可展开全部事件]
  C -- 否 --> E[查看基本运行状态]
  D --> F[复制不含简历正文、登录信息的诊断摘要]
  D --> G[打开本机日志目录查详细记录]
  F --> H[用于定位失败阶段和恢复入口]
  G --> H
```

## 模块之间怎样衔接

```mermaid
flowchart LR
  A[简历与求职方向] --> B[今日任务]
  B --> C[发现岗位]
  C --> D[岗位记录]
  D --> E[沟通清单与记录]
  E --> F[消息与回复]
  F --> G[求职体检]
  D --> G
  G --> B
  D --> H[简历工作室]
  H --> I[面试训练]
  J[招聘平台] --> C
  J --> F
  K[模型与设置] --> A
  K --> C
  K --> F
  L[运行诊断] -.问题定位.-> C
  L -.问题定位.-> F
```

这些图是当前实现的路径说明，不保证外部招聘平台永远提供完整页面。如果页面不可读或安全状态无法确认，系统会停止相关读取并保留进度；它不会据此猜测岗位匹配，也不会代替用户确认对外发送。
