# 简历驱动首次使用流程

## 目标

新用户从自己的简历和求职偏好出发，不从内置 AI 关键词出发。系统负责给初始建议，用户只需要确认影响搜索的少量条件。

## 用户路径

```text
当前源码构建的安装版用户点击桌面或开始菜单的应用图标；源码或便携版用户运行 Start.bat
  -> 选择 BOSS、智联或两个招聘平台，并检查所选平台的登录状态
  -> 填写 API Key 并实测模型连接
  -> 上传简历或粘贴文本
  -> 本地提取和质量诊断
  -> 模型生成 CandidateProfile
  -> 先保存画像与简历版本
  -> 模型推荐 Search Plan
  -> 用户选择城市并调整经验、薪资、关键词
  -> 保存方案
  -> 查看所选平台当前搜索条件，按需调整并重新读取
  -> 在今日任务选单平台或双平台同时找岗
  -> 查看岗位结果；要主动联系时另行确认清单并开始沟通
```

如果用户把项目交给 Agent，Agent 不执行上述前端步骤。每次使用先运行 `agent-onboard --resume <path> --operation-id <uuid> --agent`：简历未变化就复用已保存的画像、匹配偏好卡和搜索计划；首次使用或简历变化时才通过当前进程的 stdio 协议生成它们。Agent 检查并用 `agent-confirm` 确认匹配卡后，再使用带 `--agent` 的 CLI 继续后续工作。相同 UUID 只表示同一条命令重试，下一次使用生成新 UUID；只有用户明确要求时才加 `--refresh-profile` 强制重新分析。OfferGo 不保存 Key，也不从项目内部启动第二个 Agent。详见 [Agent 无界面运行](agent-operation.md)。

模型配置位于使用链路前面，但不会封锁历史数据：未配置模型时仍能查看已有岗位、投递记录和诊断信息。

## 第一次启动浏览器

1. 当前源码构建的安装版点击桌面或开始菜单图标；源码或便携版才双击 `Start.bat`。当前仓库源码默认启动“OfferGo 专用 Edge（推荐）”，公开 v1.3.2 安装版仍显示“RoleFlow 专用 Edge（推荐）”。默认路径不需要 Edge Control。
2. 在“招聘平台”选择要使用的 BOSS、智联或两者，并在专用 Edge 登录所选平台。工作区会准备所需的搜索页和消息页；BOSS 固定基线是同一窗口中的 `BOSS-SEARCH` 与 `BOSS-COMMUNICATION`。页面未就绪时按工作区提示恢复。
3. 浏览器登录资料保存在 `%LOCALAPPDATA%\RoleFlow\BrowserProfile`。标准安装版的数据库、简历、模型设置、日志和报告另存于 `%LOCALAPPDATA%\RoleFlow\Data`，均独立于程序目录；便携版或显式指定数据目录的运行方式按其启动参数保存。
4. 启动助手可在就绪检查后引导一次前台；完成启动后，扫描、JD 读取、分析、消息发现和沟通都在后台运行。

源码或便携版明确要复用日常 Edge 时，才运行 `Start.bat -BrowserMode edge`。这个“使用当前 Edge（高级，需要浏览器连接组件）”路径要求已有 Edge Control 扩展与桥接健康；推荐的专用 Edge 失败时不会自动切换到它。

## 简历入口

- TXT / MD：直接读取 UTF-8 文本。
- DOCX：读取正文、页眉和页脚。
- PDF：读取文本层；疑似扫描件时明确提示粘贴文本，不伪装成已完成 OCR。
- 文本粘贴：最稳定的兜底，并提供包含求职意向、教育、经历、项目、技能和优势的模板。

解析过程中的临时文件写入数据目录下的 `.runtime\resume-parse`，处理后删除。上传的简历原文件会另存于本地用户数据目录，供简历版本管理；提取文本和结构化结果存入本地 SQLite。粘贴文本没有原文件可保存。

## 画像原则

- 用户输入视为已确认事实，不要求逐字段重复确认。
- 模型只整理材料，不得编造公司、时间、职责、学历、结果或技能。
- 页面不在解析阶段点评简历，也不追问毕业月份、四级分数、团队人数等与岗位筛选无关的信息。
- GAP、离职原因、到岗时间和短期项目口径不能仅凭简历生成；只有 HR 实际提问时才按需询问一条事实。

## Search Plan

模型可以推荐：

- 目标岗位方向和 A/B/C 搜索关键词。
- 薪资范围、经验范围和 3–5 年可冲策略。
- 全职类型、学历、排除词和扫描规模。

城市由用户选择；只有简历明确写出求职城市时才能预填。保存后的方案绑定具体画像版本，画像更新后旧方案标记为 stale，必须重新确认，避免用旧条件扫描。

真实扫描启动前，“今日任务”会读取并展示所选平台当前搜索条件，也提供“重新读取搜索条件”。重复的智联搜索页由工作区按已保存条件管理。已启动的一轮使用冻结的条件，页面随后变化只影响下一轮。BOSS 固定搜索页有效时，项目会继承其中的城市、区域、薪资、经验、学历和行业等条件，只替换搜索关键词；其他模式按各自现有方案规则执行。首次使用仍必须保存 Search Plan，它负责画像依赖、关键词优先级、本地匹配偏好和缺省筛选条件。

首次生成通常调用模型两次：先解析简历画像，再根据画像推荐 Search Plan。任一步失败都会显示明确错误；已保存的历史岗位和状态仍可查看。

## 验收

离线回归覆盖文件解析、粘贴文本、模型连接、画像持久化、简历版本、方案保存、过期依赖、队列、工作流和沟通状态。真实 BOSS 只在离线检查通过并冷却充分后做小样本串行验收；采集校准和沟通校准分开执行。
