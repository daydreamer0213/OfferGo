# 07 设置、资料与异常恢复

[返回指南首页](README.md) · [上一章：求职体检](06-job-search-review.md) · [下一章：当前状态与文档地图](08-status-and-documents.md)

本章解释支撑所有模块的三件事：招聘平台怎样连接，模型怎样工作，资料和中断怎样保存。日常使用不需要了解浏览器控制协议或数据库命令。

## 1. 招聘平台：准备一个可核对的工作区

进入 **招聘平台**，选择 BOSS、智联或两个平台，保存后按页面提示准备工作区，并在专用 Edge 中完成登录。

普通安装方式默认使用 **OfferGo 专用 Edge（推荐）**。第一次需要你登录；之后复用这份浏览器登录资料。专用 Edge 与模型服务是不同连接：模型测试通过，不代表招聘平台已登录。

### 为什么要固定页面与核对身份

读取岗位时，程序需要知道“当前看到的内容究竟属于哪个岗位”；发送时，还必须知道“现在准备联系的是不是清单中的那个人”。如果同时开很多重复页面、切换登录身份或在任务中改变页面，原来的判断可能失效。

因此，BOSS 主要使用同一窗口中的固定搜索页与沟通页，程序按当前绑定重新识别它们，操作前后核对岗位或会话。消息发现有一条受限制的临时详情读取路径，用来补充陌生会话缺失的 JD；它不是为每个岗位开一个并行窗口。

启用双平台，意味着系统可以分别安排两平台任务，不意味着单个平台内可以并行点击多个岗位。

### 随机等待与暂停在做什么

平台读取包含随机间隔、阶段休息、访问额度和进度保存。它们共同控制访问节奏。出现登录失效、验证页、风险提示、页面丢失或身份不明时，受影响的操作会停止。

这些限制可能让一次任务分阶段完成。尚未读完的岗位应保留为待办，不能因为本次读不到，就被当作“不适合”。本次开发测试中授权使用的额度或间隔例外，只属于测试安排，不是普通用户的正式使用策略。

### 当前默认节奏怎样限制一轮

以下为本次源码的正式默认值，不是要求用户必须完成的投递指标：

| 项目 | 默认安排及含义 |
| --- | --- |
| 联系目标 | 每日目标 70、每轮上限 40；实际仍取决于可用岗位、用户选择与结果核验 |
| 轮次 | 每天最多 3 轮，前两轮为常规轮，第三轮只在库存不足等条件成立时追加 |
| 扫描轮次间隔 | 默认 120 分钟；页面提供的“提前开始下一轮”需要明确确认，只解除这一次轮间限制 |
| 获取预算 | 每轮最多 120 份详情、20 页搜索；日共享上限为 360 份详情、60 页搜索 |
| BOSS 详情动作 | 有 8—14 秒随机间隔，并叠加阶段休息；不是所有动作都统一等待这个时长 |

提前开始也保留随机动作间隔、周期休息、访问记账和风控停止。模型可以并发处理已保存的岗位资料，不代表招聘页面可以并行点击。

## 2. 模型与设置：理解内容的两类任务

模型服务可以理解为项目使用的外部分析工具。**API Key** 是访问该服务的密钥，按页面提供的输入框保存即可。

| 配置 | 主要处理什么 | 为什么分开 |
| --- | --- | --- |
| 深度分析 | 简历资料、回复与其他内容生成等任务 | 需要组织较完整的上下文与表达 |
| 批量筛选 | 岗位理解、匹配及对应恢复 | 找岗过程中会反复处理岗位，参数需求可能不同 |

两项默认可共享服务商和密钥，但各自的模型参数分别保存。是否使用同一模型，由配置决定。

### 正确的配置顺序

1. 打开 **模型与设置**，填写服务地址、模型名称与 API Key，或使用页面提供的预设。
2. 点击 **测试连接并保存**。主配置会测试对应任务；看到验证成功后，才把新配置视为可用。
3. 如果只保存了参数，或使用了 **恢复推荐值**，再测试一次。保存成功只是参数落盘，不等于模型已经能正常响应。
4. 后续生成或分析失败，先核对当前任务使用哪项配置，再看该项的连接状态与错误。

**连接通过与内容质量是两回事。** 连得上只能说明请求能够完成，不能保证推荐合理、故事具体、简历不夸大。模型生成的结果仍按对应模块的内容标准检查。

用于匹配的模型、基础资料或分析依据变化时，部分已保存判断可能被标记为过期；后续需要使用时再更新。不要把旧页面上仍存在的结果，理解为已经按新配置重新分析过。只启用一份新的投递简历，不等于自动替换基础匹配资料。

## 3. 资料保存在哪里，哪些会联网

### 本机保存

项目把简历、画像、搜索方案、岗位记录、消息、草稿、训练与反馈记录保存在本地资料目录。它使用本地数据库组织记录，并保留原文件、设置、报告和日志。

标准安装版沿用这些兼容路径：

| 内容 | 位置 |
| --- | --- |
| 求职业务资料及运行数据根目录 | `%LOCALAPPDATA%\RoleFlow\Data` |
| 专用 Edge 登录资料 | `%LOCALAPPDATA%\RoleFlow\BrowserProfile` |

在 Windows 文件资源管理器地址栏粘贴对应路径即可打开。目录名仍叫 RoleFlow 是历史兼容，不代表资料丢失。程序安装位置与这些用户资料目录分开，更换安装目录不等于新建一套空资料。

源码、便携版或 Agent 可以指定另外的数据目录。**只有使用同一个数据目录，两个入口才会看到同一份实际记录。** 端口不同不一定意味着资料不同；程序名称相同也不代表读取的是同一份资料。

### 联网处理

本地保存不等于所有处理都离线。招聘平台需要联网；使用云模型时，会发送本次任务所需的简历、岗位描述、消息或其他上下文。不同任务发送的范围不同。

项目有隐私处理和脱敏逻辑，但用户仍应把模型提供商视为会接触任务内容的外部服务，不能因为页面在本机打开，就认为简历永远没有离开电脑。

API Key 在 Windows 上使用当前用户的系统加密能力保存，不作为普通求职记录写入数据库。换电脑或换 Windows 用户后，不能靠复制旧密文来保证可用，应重新配置。浏览器登录资料也不应随便复制到别人的电脑或放进公开仓库。

## 4. 出问题时，先分清是哪一类

| 看到的情况 | 它说明什么 | 具体处理 |
| --- | --- | --- |
| 工作台打不开 | 本地程序可能还没启动就绪 | 从 OfferGo 图标重新查看启动进度；安装版通常在就绪后打开本机页面 |
| 页面要求登录或安全验证 | 平台连接尚不可用 | 在对应平台完成登录或验证，再检查工作区就绪状态 |
| 模型连接或请求失败 | 内容分析没有正常完成 | 到模型设置核对对应任务，测试连接，再回原任务处理失败项 |
| 岗位显示等待补齐资料 | 分析依据还不完整 | 按页面提供的补读入口处理；不把它理解为不推荐 |
| 本轮已暂停 | 进度保留，暂时不继续 | 先看暂停原因，条件恢复后使用“继续本轮” |
| 本轮已结束 | 这轮已关闭 | 已保存结果仍在；后续另开一轮，不把结束当暂停 |
| 发送结果不明确 | 无法确认外部动作是否已经成功 | 先到原平台核实，避免直接重复发送 |
| 页面与旧说明不一致 | 可能使用了不同版本或数据目录 | 核对当前版本与入口，参看[版本区别](08-status-and-documents.md) |

安装版启动就绪后默认工作台地址为 `http://127.0.0.1:8787/`。开发预览可能使用其他端口，应以当次启动显示的地址为准；本项目当前预览地址不应成为所有用户固定填写的地址。

如果因模型超时或配置问题自动暂停，按 **测试批量模型连接 → 测试连接并保存 → 回原轮 → 继续本轮** 处理。普通手动暂停且没有模型故障时，可在核对状态后继续，不必为了恢复重复测试连接。

## 5. 运行诊断：带着具体问题找证据

进入 **运行诊断**，默认先看最近的警告和错误。页面提供：

- **查找排错编号**：把出错页面提供的编号粘贴进去，定位同一次请求的记录。
- **复制诊断信息**：获取版本、工作区和运行状态摘要，便于求助。
- **打开日志文件夹**：打开本机详细日志位置，进一步核对发生过什么。

复制的诊断摘要不包含简历、岗位正文、登录信息或本机文件路径。详细日志属于本机排错材料，分享前仍需检查内容。不要通过删除数据库、清空浏览器登录资料或手改状态来“试着修复”。

## 6. 为什么恢复进度比重新来一遍重要

读取、模型分析和外部沟通的后果不同：重新分析一个本地岗位主要增加成本；重复联系同一 HR 可能产生真实干扰。因此系统分别记录已经保存的资料、任务状态和外部结果。

恢复时，应从当前明确的状态继续：完整资料尽量复用，未完成项保留待处理，外部结果不确定的项先核验。它不会把所有失败都简单转换成“从头再点一次”。
