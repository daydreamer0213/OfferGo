# 06 求职体检：根据什么判断先改哪里

[返回指南首页](README.md) · [上一章：面试准备](05-interview.md) · [下一章：设置、资料与恢复](07-settings-data-and-recovery.md)

求职体检检查的是**求职进展与真实反馈**。它帮助你决定接下来先查哪里；简历工作室负责实际编辑，两者不是同一个模块。

当前有两条互相补充的路径：**一条具体反馈可以支持一次具体检查；足够成熟的样本才能支持总体统计提醒。**

## 1. 哪些记录能用于体检

扫描、查看、分析和推荐都不等于投递。系统需要可核对的联系起点，例如用户确认已投、已核验成功的主动沟通，或已确认发送的回复；同一候选人的同一岗位不会按消息条数重复计数。

样本绑定候选人、方案、平台、策略轮次、起始时间和对应简历版本。这样才能知道“哪批机会使用了什么材料”。

**收到 HR 主动招呼**另有联系展示。仅有对方来信，不会自动补成你已经主动投递，也不能随意放进当前方案的主动联系分母。

## 2. 为什么刚联系后不能马上判断失败

默认观察窗口是联系起点后 48 小时；若截止时间按中国时区落在周六或周日，顺延到周一同一时刻。例如周五下午联系，原截止在周日下午，就顺延至周一下午。

这是周末顺延，不是完整的法定节假日工作日历。已成熟样本刚出现“已读但未回复”时，对这个回复阶段还会重新留出等待窗口。

系统区分：

- **有正向进展**：收到回复、约面等事实可以立即显示。
- **还在等**：尚未经过观察窗口，暂不当作失败。
- **不知道**：平台没提供可靠状态，不等同明确未读、拒绝或无效。

因此，页面当前看到的正向数量，与能够用来诊断的成熟样本数量可能不同。

## 3. 每个指标的分母是什么

体检关注阶段之间的推进，而不是把所有百分比都除以“总共扫到多少岗位”。下面的统计诊断只使用对应阶段成熟、已知且满足前序条件的样本；等待与未知按该阶段排除。

| 阶段 | 主要在什么范围里看下一步 |
| --- | --- |
| 已联系 → 已读 | 阅读状态可核对的成熟联系样本 |
| 已读 → 回复 | 已读、回复状态可核对，且不在新已读等待窗口的样本 |
| 回复 → 有效沟通 | 已回复且有效沟通状态可核对的样本 |
| 有效沟通 → 索要简历 | 已有有效沟通且索简历状态可核对的样本 |
| 有效沟通 → 面试邀请 | 已有有效沟通且约面状态可核对的样本，和索简历分开 |
| 面试邀请 → 确认面试 | 已获邀请且安排状态可核对的样本 |
| 确认面试 → 完成面试 | 已安排且完成状态可核对的样本 |
| 完成面试 → Offer | 已完成且 Offer 状态可核对的样本 |

“有效沟通”来自已有消息意图和事件，例如意向确认、资料询问、面试邀请或索简历，不代表系统已经测出 HR 对你“很满意”。

### 用一组虚构数字看口径

假设联系了 40 个岗位，其中 32 个已成熟、8 个还在等待。成熟岗位里：

- 20 个已读、10 个明确未读、2 个阅读状态未知。
- 20 个已读岗位中，5 个已回复、12 个经过等待仍未回复、3 个刚出现新已读还要继续等。

此时，阅读率按 **20 ÷ 30** 看，条件回复率按 **5 ÷ 17** 看。不能把它们都用 40 作分母。

页面的大数字可能显示全部样本已经发生的即时进展；旁边“可核对”才对应统计判断的范围。累计记录的“已回复 ÷ 已联系”又是另一种回顾口径，不应与上述条件回复率混用。

### 平台分别看

BOSS 和智联的状态可见性不同。智联不显示与 BOSS 相同的已读阶段，诊断会跳过依赖已读、送达的前两项检查，而不是把缺失状态当作低回复表现。

## 4. 有多少样本，系统才开始给总体提醒

当前默认分级是：

| 成熟样本 | 总体统计怎样使用 |
| --- | --- |
| 少于 30 | 主要展示事实，不据此诊断总体瓶颈 |
| 30—49 | 初步观察 |
| 50—69 | 阶段诊断 |
| 70 及以上 | 按当前策略进入正式统计诊断层级 |

30/50/70 是项目的内部可配置门槛，不是每一批必须投递的数量，也不是达到 70 就自动换策略。

如果未知状态达到成熟样本的一半，仍不判断主要瓶颈；具体阶段还需要至少 10 个已知结果，并覆盖至少一半该阶段合格样本。样本多但关键结果不知道，也不能硬下结论。

### 当前提醒怎样选方向

程序按固定顺序返回第一条达到条件的提醒，不是在比较所有因素后证明了根因：

| 观察到的信号 | 默认提醒线 | 优先检查 |
| --- | --- | --- |
| 已约面但确认安排少 | 至少 10 个约面样本，确认率低于 50% | 时间安排、邀请确认和后续沟通 |
| 联系后已读少 | 已读率低于 40% | 招聘活跃度、岗位选择、联系时机与开场 |
| 已读后回复少 | 条件回复率低于 35% | 岗位匹配与开场表达 |
| 已回复却少有效沟通 | 有效沟通率低于 50% | 回答是否覆盖 HR 的实际问题 |
| 有效沟通后少面试邀请 | 约面率低于 25% | 简历是否发送、后续沟通；再结合原话检查项目或技能表达 |

这些比例是检查提示，不是行业合格线，也没有证明低于某个比例就一定是哪一项出了错。尤其不能看到没回复，就立即要求重写整份简历。

## 5. 一条真实反馈怎样变成具体检查

总体样本不足，不代表要忽略 HR 已经明确问过的问题。当前“根据实际反馈，先检查什么”会走另一条路径：

1. 在当前方案和有效策略的联系样本里，核对岗位、平台、会话与时间。
2. 读取已保存的 HR 原话、可靠的已有分类，以及后续实际观察到的本人消息。
3. 根据原话主题形成检查项，例如本人职责、方法、结果、薪资、时间或具体条件。
4. 展示岗位、公司、原话，以及可用的 JD、历史简历与本人回答，供你核对。
5. 优先展示有具体依据的检查，再回到统计提醒。

一条有效原话可以支持“检查这一处”，不需要等到 30 个成熟样本。**它仍不足以证明所有机会的总体瓶颈。** 已有分类可靠与身份对应也是前提，系统不会拿任意一句摘要冒充 HR 原话。

核对材料也有版本边界：JD 是当前本地记录，简历是该联系样本绑定的本地版本。它们不能证明招聘网页当时的全部内容、实际发送的附件版本或 HR 已经读过简历。

### 三个具体例子

**HR 问：“库存同步项目你具体负责哪部分？”**

先看你当时的回答是否说清接口、校验还是整体架构；再看原简历是否同样含糊。有问题就改对应项目的职责表达，不必重写教育背景，也不能据一次询问断定 HR 已否定能力。

**HR 明确说：“薪资上限与期望不一致，这次不继续。”**

有对应分类与原话时，先核岗位薪资范围和真实期望，决定要不要调整后续范围。改项目成果解决不了薪资冲突，也不能替用户编一个更低期望。

**HR 只说：“暂不合适。”**

记录机会结束，原因仍不明确。当前没有一个能从所有拒绝文字中可靠还原原因的通用归因器，不能补写成技术、学历或薪资不足。

面试完成后还没结果，也先核对反馈与下一步安排，不自动判成面试失败；已经有 Offer 时，优先核对条件和后续事项。

HR 索要简历不等于已经发送；即使记录了发送动作成功，也不能据此证明发出的是当前本地简历版本。涉及附件内容时，仍需到对应平台核对。

## 6. 指出方向后，怎样真正修改

| 应检查什么 | 去哪里做 | 系统当前帮到哪一步 |
| --- | --- | --- |
| 搜索范围或求职条件 | 当前方案与平台条件 | 给检查依据；由用户修改实际条件 |
| 开场与回答表达 | 原会话、消息与回复 | 核对原话和本人已发送内容，修改后另行确认 |
| 项目、技能或职责表达 | 简历工作室 | 可跳转，但仍需选择参考简历、必要时选岗位，编辑对应部分 |
| 项目深度和解释能力 | 面试训练 | 根据真实经历准备故事，再练具体追问 |
| 面试安排和实际进展 | 原对话或本地进展记录 | 核对并补充事实，不把等待写成失败 |

目前体检不会自动定位简历章节、预填拒绝原话或生成一份已经定向修改好的稿件。它提供可追溯的线索，简历与面试模块承担各自的整理和练习职责。

## 7. 改完以后，为什么要分策略轮次

如果修改前后的岗位范围、简历或招呼方式混在一起，就很难知道统计结果对应哪种做法。

手动调整后，可使用 **记录方案调整**，选择影响全部平台还是某个平台，并说明调整类型。这个动作记录比较边界，不会替你修改搜索条件。启用新简历也会登记相应的简历策略变化。

新旧反馈各归原来的联系样本与轮次，不会因为今天修改方案，就把昨天的联系搬进新轮。展示可直接比较的前后回复比例，需要方向一致、策略边界明确，两轮的成熟数与回复状态明确数都达到各自可比较门槛（默认 50），而且本轮没有同时记录多类调整。否则会说明不能比较、样本不足或多项调整混杂，不能声称知道单项变化的作用。

回复比例变好只说明观察到变化，不证明一定是某项修改造成。后续应继续看同类机会的具体反馈和表现。

## 8. 结果不足时，应该得到什么说明

没有可靠联系记录时，应显示数据不足，而不是用扫描量造出投递效果。有具体原话时，先查原话；没有原因时，就保留未知。

“联系较久、建议核对进展”的提醒目前按联系起点等条件计算，不应解释为程序已经证明最后一条新消息恰好发生在七天以前。

这个模块做得好，表现为你能说清“为什么先检查这里、对应哪条材料、去哪里改”，而不是只看到一组比例和“优化简历”四个字。
