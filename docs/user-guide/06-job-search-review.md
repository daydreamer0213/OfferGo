# 06 求职体检：接下来先改哪里

[返回指南首页](README.md) · [上一章：面试准备](05-interview.md) · [下一章：设置、资料与恢复](07-settings-data-and-recovery.md)

联系了一些岗位后，求职体检帮助你看两件事：**HR 的具体反馈提醒了什么，整体进展又卡在哪一步。** 看完应能找到一件值得先检查的事，以及对应的修改入口。

## 1. 打开页面后，先看哪里

先看 **根据实际反馈，先检查什么**。这里会列出能对应到岗位和原话的检查建议。没有具体反馈时，再看下面的联系、回复和面试进展。

例如，HR 问“库存同步项目你具体负责哪部分”，可以先打开原对话，检查回答是否说清本人分工；如果简历也只写“参与项目”，再把这一段改具体。

一条明确反馈就可以开始这类检查。整体回复率和约面情况，则在积累一段时间后再看。

## 2. 系统怎样从反馈中挑出检查方向

系统先找到该岗位的 HR 原话、你的后续回答和相关资料，再按问题主题整理：

| 反馈内容 | 先检查什么 |
| --- | --- |
| “你具体负责哪部分？” | 本人分工是否讲清，项目描述是否过于笼统 |
| “为什么用这种方法？” | 是否解释选择依据、作用和取舍 |
| “最后效果怎么样？” | 是否写出了实际交付、观察或验证结果 |
| 薪资、到岗或面试时间问题 | 双方条件和安排是否一致 |
| 只有“暂不合适” | 保留结束记录，等有具体说明后再决定调整什么 |

检查卡把建议与岗位、原话放在一起，方便对照。原话能说明对方问了什么，你的回答能说明当时讲了什么，两者结合才容易找到值得改的地方。

已经收到 Offer 时，先核条件和后续事项；面试后还在等消息时，先核反馈与下一步安排。

## 3. 找到问题后，去哪里改

| 要改进的地方 | 具体操作 |
| --- | --- |
| 岗位范围、薪资等条件 | 查看当前方案与平台条件，按实际意愿调整 |
| 招呼和回答表达 | 打开原会话，对照 HR 问题修改回复 |
| 项目、技能、本人职责 | 点“检查项目经历描述”进入简历工作室，选参考简历并编辑对应部分；岗位模式再选目标 JD |
| 项目的解释深度 | 进入面试训练，选相关故事练习方法、依据与结果 |
| 面试安排或实际进展 | 查看原对话，补充时间、结果和下一步记录 |

比如，HR 明确说薪资上限与你的期望不一致，就先看薪资范围；把项目写得更长通常解决不了这件事。

页面中的本地 JD 和历史简历可供对照。若要确认当时发的是哪份附件，到对应平台查看发送记录。

## 4. 改完以后，怎样观察有没有帮助

调整搜索范围、招呼方式等内容后，使用 **记录方案调整**，选影响哪个平台、改了哪类内容。启用新简历时，系统也会记录相应变化。

每次调整前后的记录分开保存，便于知道哪批机会用了什么做法。旧岗位后来收到回复，仍归到当时那一批；BOSS 与智联也分别看。

前后比较需要投递方向一致、两边数据足够、改动比较单一。默认要求两轮各有至少 50 个经过等待的样本，以及至少 50 个回复状态明确的样本。样本不足或同时改多项时，暂不展示前后比例对比，先分别查看实际反馈。

接下来结合回复比例和具体原话，观察新的做法是否值得继续沿用。

## 5. 这些数据从哪里来

联系统计来自实际记录：用户标记已投、系统核验成功的主动沟通，以及已确认发送的回复。同一个岗位按一次机会统计，便于持续跟踪后续。

“收到的联系”还包含 HR 主动来信，适合看有哪些人找过你；投递效果则看已联系的那批岗位。只看过或分析过的岗位保留在岗位记录中。

每条联系记录会关联方案、平台、时间、简历版本和当时的做法，让后续反馈能找到对应背景。

## 6. 为什么有些记录还在等待

对方需要时间阅读和回复。默认观察窗口是联系后 48 小时；截止在周末时，按中国时区顺延到周一同一时刻。例如周五下午联系，原截止在周日下午，就顺延至周一下午。这套顺延目前只识别周六、周日。

刚出现新的已读、还没回复时，回复阶段也会重新留出等待时间。等待中的岗位先继续观察；平台没提供的状态显示未知。

新回复、面试邀请等进展会及时显示。因此，页面上的进展数量可以先增加，统计判断稍后再纳入这条记录。

## 7. 想看懂比例，可以这样读

阶段比例会看已经过等待、状态明确的那组岗位。例如“已读到回复”，看的是已读岗位里有多少回复；“有效沟通到面试”，看的是已经聊起来的岗位里有多少约面。

| 阶段 | 比较的范围 |
| --- | --- |
| 已联系 → 已读 | 阅读状态明确的成熟联系样本 |
| 已读 → 回复 | 已读、回复状态明确，并已过回复等待窗口的样本 |
| 回复 → 有效沟通 | 已回复且有效沟通状态明确的样本 |
| 有效沟通 → 索要简历 | 已有效沟通且索简历状态明确的样本 |
| 有效沟通 → 面试邀请 | 已有效沟通且约面状态明确的样本，和索简历分别看 |
| 面试邀请 → 确认面试 | 已获邀请且安排状态明确的样本 |
| 确认面试 → 完成面试 | 已安排且完成状态明确的样本 |
| 完成面试 → Offer | 已完成面试且 Offer 状态明确的样本 |

这里“成熟”就是已经过相应等待时间。“有效沟通”指意向确认、资料询问、索简历、面试邀请等实质交流。

### 一组例子

假设联系了 40 个岗位，32 个已过等待、8 个还在等。前 32 个里：

- 20 个已读、10 个明确未读、2 个阅读状态未知。
- 20 个已读岗位中，5 个已回复、12 个过了等待仍未回复、3 个刚出现新已读还要继续等。

阅读率就是 **20 ÷ 30**；条件回复率是 **5 ÷ 17**。分母分别对应阅读状态明确、以及可以判断回复情况的岗位。

页面的大数字展示当前进展，“可核对”展示这一步能用于统计的范围。累计“回复占比”按已回复除以已联系看，用来回顾全部联系情况。

BOSS 与智联提供的状态不同。智联没有同样的已读展示时，主要看后续沟通与面试进展，跳过依赖已读的统计提醒。

## 8. 系统怎样根据整体进展给提醒

当前默认按成熟样本数量逐步提供统计判断：少于 30 时展示事实，30—49 初步观察，50—69 阶段诊断，70 以上进入正式统计诊断。具体反馈检查始终可以先用。

各环节还需要至少 10 个已知结果，并覆盖至少一半对应样本。成熟样本中至少一半状态未知时，先展示信息不足，继续积累反馈。

满足条件后，系统先检查约面安排，再沿已读、回复、有效沟通和约面的顺序，选出第一个需要关注的环节：

| 观察到的情况 | 当前提醒线 | 优先检查 |
| --- | --- | --- |
| 至少 10 个约面样本，确认安排少 | 确认率低于 50% | 时间安排、邀请确认、后续沟通 |
| 联系后已读少 | 已读率低于 40% | 招聘活跃度、岗位选择、联系时机和开场 |
| 已读后回复少 | 条件回复率低于 35% | 岗位匹配与开场表达 |
| 已回复却少有效沟通 | 有效沟通率低于 50% | 回答是否覆盖 HR 的实际问题 |
| 已有效沟通但少约面 | 约面率低于 25% | 简历是否发送、后续沟通，以及项目和技能表达 |

这些数值用于安排检查顺序，具体原因仍结合原话看。例如，已读少时先看岗位是否还活跃；对方明确追问本人职责时，就先看那段职责表达。

如果当前数据不足，继续正常找岗、处理消息并记录实际进展即可。新反馈出现后，页面会有更具体的依据。
