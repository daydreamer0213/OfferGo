# 01 首次使用：把简历变成可执行的求职方向

[返回指南首页](README.md) · [下一章：找岗与岗位判断](02-job-discovery-and-matching.md)

第一次使用，先让系统理解三件事：**你做过什么、想找什么、这次去哪里找。**

## 1. 准备招聘平台和模型

安装版从桌面或开始菜单的 **OfferGo** 图标启动，开发预览打开当次提供的地址。需要下载安装时，按[安装版说明](../installed-user-guide.md)操作。

工作台就绪后：

1. 进入 **招聘平台**，选择使用的平台，在专用 Edge 中完成登录并检查工作区。
2. 进入 **模型与设置**，填写自己的模型服务信息，点击 **测试连接并保存**。
3. 进入 **简历工作室**，上传或粘贴简历，开始建立资料。

平台登录让系统能读取岗位；模型连接让系统能理解和生成内容；上传的简历则提供判断岗位的依据。准备好这三项，就可以开始建立求职方向。

连接、资料位置及失败处理见 [07 设置、资料与恢复](07-settings-data-and-recovery.md)。

## 2. 为什么要分成四份资料

| 资料 | 它回答的问题 | 一个例子 |
| --- | --- | --- |
| 原简历 | 保留原来的经历描述，方便后续对照 | “负责检索接口与结果展示” |
| 候选人画像 | 系统怎样整理你的背景、经历与求职意向 | 本科；做过应用开发；希望在广州找工作 |
| 匹配偏好卡 | 哪些经历直接相关，哪些能用于相近工作，哪里差距较大 | 接口开发有实际项目；检索经验可用于问答应用开发 |
| 搜索方案 | 本轮按什么范围和搜索词寻找机会 | 广州、应用开发方向、按本人意愿设置薪资与经验范围 |

这些内容都从已有简历中整理，你只需检查和补充关键部分。

分开保存，是为了便于按需要更新。求职城市可能改变，做过的项目仍然保留；补充新的工作情况后，再更新对应画像和匹配卡。每份资料各有用途，调整时更容易找到位置。

## 3. 上传简历后，系统实际做什么

### 第一步：提取可读文本

支持 TXT、Markdown、DOCX 和 PDF，也可直接粘贴文字。文档先转成可分析文本，再进入简历理解。

系统先在本地提取正文，遮盖可识别的姓名、电话、邮箱等字段，再交给模型整理经历。资料保存与联网处理见[第07章](07-settings-data-and-recovery.md)。

如果 PDF 是扫描图片、提取不出文字，页面会提示粘贴简历文本。

### 第二步：整理画像和匹配卡草稿

系统把简历整理成背景、经历、能力与求职方向，并保存下来。匹配卡再把其中最值得用于找岗的内容列出来。

画像、卡片和方案会分步保存。中途失败时，可以接着处理未完成的部分，已有资料继续保留。

匹配卡中可检查的内容包括：

- **目标方向**：哪些工作方向值得寻找。
- **强证据**：已有实际项目或工作，能直接对应某类岗位的能力。
- **可迁移能力**：可以用于相近工作的能力，以及换到新场景时需要补充的部分。
- **需谨慎转向**：与现有经历差距较大的方向及原因。
- **用户补充偏好**：你希望优先考虑或避开的机会。

### 第三步：生成搜索方案

系统把求职方向变成可用于搜索的方案，再由你核对城市、薪资、经验与关键词等设置。

搜索词采用“后端开发工程师”“AI 应用工程师”等岗位名称，帮助系统找到相应工作。具体是否合适，再读完整 JD 判断。初次方案的薪资筛选留空，按你的实际期望填写。

### 第四步：你确认，系统才使用这套依据

打开匹配卡草稿，修正误解后先 **保存草稿**，再点击 **确认匹配偏好卡**。已准备好的同画像方案可随之启用；继续检查方案，需要调整时再保存。

确认新卡会替换此前的已确认卡，旧卡保留为历史。基于旧卡的方案需要重新保存，避免“页面上看的是新能力，后台仍按旧依据找岗”。

完成后，你会看到已保存的资料、已确认的匹配卡和可使用的搜索方案，可以进入 **今日任务** 开始找岗。

## 4. 核对时到底看什么

重点检查经历分工和求职意愿是否准确：

| 系统整理的内容 | 怎么判断 |
| --- | --- |
| “独立负责整个产品” | 实际负责某个模块时，改成该模块的具体工作 |
| “具备接口开发经验” | 查看是否对应到了自己做过的项目或工作 |
| “愿意转到算法研究” | 放在求职方向里，能力部分仍按已有经历整理 |

例如，希望找 Agent 应用开发，可以作为搜索方向；简历里的接口、检索或工具接入工作，则用来判断具体岗位的相关性。意愿与已有能力分开，推荐理由才更清楚。

## 5. 搜索条件与平台页面如何配合

城市、薪资、经验等平台筛选会直接影响能搜到哪些岗位。

开始前，在 **今日任务** 查看当前平台搜索条件。发现与期望不一致时，先到平台调整，再点 **重新读取搜索条件**。

沿用当前平台条件时，系统保留这些筛选，按本轮任务更换关键词。例如，当前限定广州，搜索不同岗位名时仍在广州范围内找。

因此，先把搜索范围设合适，再由岗位分析比较具体工作和经历。

## 6. 之后为什么通常不用重新上传

资料、匹配卡和方案会保存在本地。下一次应从已有方案进入，启动新一轮找岗。

相同简历已有可用结果时，现有流程可以复用资料；资料变动或明确刷新时，才重新生成相关结果。具体旧判断是否失效，由它使用的简历、匹配依据和分析版本决定，见 [02 岗位判断](02-job-discovery-and-matching.md)。

如果只是尚未确认匹配卡，应打开现有草稿确认，不必重复上传同一份文件。若当前没有看到旧资料，先核对是否启动了另一份数据目录。

## 7. 交给 Agent 使用时，有什么区别

外部 Agent 就是可以受托执行操作的 AI 助手。它可以通过命令行整理资料和找岗，由自己提供分析回答。

它与网页使用同一套求职规则。使用相同数据目录，就能接着已有资料和记录继续处理。

命令细节放在 [Agent 操作说明](../agent-operation.md)，不影响普通用户按本章完成首次使用。
